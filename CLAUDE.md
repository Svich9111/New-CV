# «Чувства AI» — правила проекта для агентов Claude Code

Telegram Mini App и бот для пар: у каждого партнёра личный ИИ-агент с долговременной памятью;
сообщение партнёру проходит конвейер «черновик → одобрение → безопасность → тон → адаптация →
контроль смысла → доставка».

## Стек

- Сервер: Python 3.12+, FastAPI, SQLAlchemy 2 (async), Alembic, PostgreSQL 16 + pgvector, Redis.
- Клиент: React, TypeScript, Vite, Telegram Mini Apps SDK.
- Бот: Telegram Bot API (`bot/`).
- Инфраструктура: Docker Compose (`infra/`), GitHub Actions (`.github/workflows/`).

## Команды

```bash
make install      # зависимости backend + frontend
make lint         # ruff + mypy + eslint + tsc
make test         # pytest (нужен PostgreSQL с pgvector, см. ниже) + vitest
make db-up        # PostgreSQL и Redis в Docker для локальной разработки
bash infra/agent-tools/install.sh   # RTK + Serena глобально, на все проекты (docs/AGENT_TOOLS.md)
```

Тесты backend берут адрес БД из `TEST_DATABASE_URL`
(по умолчанию `postgresql+asyncpg://postgres:postgres@localhost:5432/feelings_test`).

В облачной сессии тестовый PostgreSQL — отдельный кластер `/var/tmp/feelings-pgdata` (порт 5432, вход `trust`,
расширение pgvector). Системный кластер (`/var/lib/postgresql/16/main`, проверка пароля) не запускать — тест роли
входа `feelings_api` на нём падает. Если кластер не запущен:
`su postgres -c "/usr/lib/postgresql/16/bin/pg_ctl -D /var/tmp/feelings-pgdata -o '-p 5432 -k /tmp' -l /var/tmp/feelings-pgdata/log start"`.
Роли `feelings_*` общие для всего кластера — менять их только в откатываемых транзакциях.

## Семь принципов продукта (ТЗ, раздел 2) — обязательны для кода, промптов и интерфейса

1. Агент — переводчик, а не адвокат.
2. Слова остаются вашими: ни одно сообщение не уходит без явного «Отправить».
3. Смягчать форму, не смысл; пометка «адаптировано», оригинал по запросу.
4. Исповедь приватна: личный чат не видят партнёр и его агент.
5. Мост, а не замена: цель — живой разговор.
6. Память под контролем: человек видит и удаляет любую запись.
7. Границы: не терапия; при насилии/угрозах/кризисе — ничего не смягчать, направить к специалистам.

## Жёсткие правила

- Ключи и токены — только в переменных окружения (`.env`, не коммитится). Шаблон — `.env.example`.
- Агенты работают только с выдуманными данными. Доступа к продуктивной базе и перепискам нет.
- Любой запрос к личным данным идёт через слой доступа (`backend/app/repositories/`) с проверкой
  владельца; прямой SQL в обработчиках (`backend/app/api/`) запрещён.
- Контекст ИИ-агента собирается только из данных владельца и одобренных сообщений пары (ТЗ 6.1, 9.2).
- Контракт API (`api/openapi.yaml`) меняет только A1; остальные предлагают изменение через карточку.
- Изменение промпта — новая версия файла в `prompts/` и прогон эталонного набора; без прогона слияния нет.
- Миграции БД, выкладка в продуктив и платёжные настройки выполняются только после подтверждения
  оператора (RoadMap §4). Толкование для локальной и временных тестовых БД — `DECISIONS.md`, АР-4.
- В журналах и `audit_log`/`safety_events` нет текстов сообщений.
- Агент не отмечает задачу готовой при красных тестах и не отключает/ослабляет тесты.
- Задача не считается готовой без отчётов ревьювера (A6) и тестировщика (A8) в `docs/reviews/`
  и без строки сверки с ТЗ (см. `docs/PROCESS.md`).
- Отступление от ТЗ возможно только через запись в `docs/DECISIONS.md` с решением оператора.
