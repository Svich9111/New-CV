## 4. Дефекты

- **[MAJOR] A8-1.5-D2** `frontend/src/api/client.ts:168-174` — на 2xx тело, которое не JSON (HTML от прокси или
  заглушки с кодом 200), превращается в `null` и возвращается как успешный ответ. Последствия, подтверждённые в
  Chromium на собранной сборке:
  (а) «Помощь» (`screens/Help.tsx:32`, `list.length` на `null`) навсегда остаётся на «Загружаем контакты…», запасной
  112 не показывается, в консоли `pageerror: Cannot read properties of null (reading 'length')` — скриншот
  `light-12-help-html200.png`;
  (б) входящее приглашение (`screens/Incoming.tsx:106`, `state.invite.inviter_name`) роняет отрисовку — пустой экран,
  без ссылки «Помощь» (`rootHtmlLen: 0, helpButtons: 0`), скриншот `light-13-incoming-html200.png`;
  (в) `GET /couple` → `null` трактуется как «пары нет».
  Ожидается: 2xx с телом не того вида — `ApiError`, а «Помощь» при любой ошибке показывает запасной 112 (ТЗ §9.3
  «контакты помощи доступны всегда»; карточка: «Помощь… запасной 112»). Тесты: `client.a8.test.ts`
  `A8-1.5-D2` (2 шт.) и факт `200 с HTML на /help/contacts сейчас даёт null`. В UI-тест не вынесено: необработанное
  отклонение из `Help.tsx` валит прогон vitest — проверено в Chromium.
- **[MAJOR] A8-1.5-D1** `frontend/src/api/client.ts:155-166` — у запросов нет таймаута (нет `AbortSignal`).
  Повисший `POST /auth/telegram` оставляет «Входим через Telegram…» навсегда: ни причины, ни «Попробовать снова»;
  повисший `GET /help/contacts` — «Загружаем контакты…» без номера 112. Ожидается: ограничение времени запроса
  (например, 15–20 с) → `ApiError(0, "network")` → причина подписью и повтор (карточка: «обрыв связи при входе —
  причина подписью, повтор там, где помогает»); на «Помощи» 112 виден сразу, не дожидаясь сервера (ТЗ §9.3). Тесты:
  `client.a8.test.ts` и `App.a8.test.tsx` `A8-1.5-D1`; факт про «Помощь» — «/help/contacts повис — пока загрузка,
  номера 112 на экране нет».
- **[MINOR] A8-1.5-D3** `frontend/src/telegram/MainButton.tsx:53-66` — цвета MainButton (`setParams`) задаются
  только при смене `text`/`disabled`/`progress`; на `themeChanged` не пересчитываются. После переключения светлой
  темы на тёмную недоступная кнопка остаётся `#d9d5d1`/`#5f5a55` вместо `#2c2c2c`/`#a8a29d` (скриншот
  `switch-05-onboarding-light-to-dark.png`). Ожидается: цвета MainButton из токенов текущей темы (карточка: «цвета
  MainButton берутся из токенов; смена темы на лету»; ТЗ §8 «тёмная тема… следует теме Telegram»). Тест:
  `App.a8.test.tsx` `A8-1.5-D3`. Причина недоступности при этом остаётся подписью — поэтому MINOR.
- **[MINOR] A8-1.5-D4** `frontend/src/app/App.tsx` — нет границы ошибок (error boundary): любое исключение при
  отрисовке размонтирует всё приложение, человек видит пустой экран без ссылки «Помощь» (воспроизведено через D2б).
  Ожидается: запасной экран «Что-то пошло не так» со ссылкой на «Помощь» и 112 (ТЗ §9.3). Отдельного теста нет —
  проверено в Chromium (`incoming-html.cjs`).

## 5. Замечания (не дефекты)

1. Текст 429 «Слишком много запросов подряд» расходится со смыслом `rate_limited` в контракте («исчерпан дневной
   лимит реплик», `Retry-After` до суток — будет «через 86400 с.»). Для путей 1.5 429 в контракте нет; учесть в 2.2.
2. `screens/Invite.tsx:144` — `aria-label` на `<p>` без роли: часть экранных дикторов имя у абзаца не озвучивает.
   axe это не отмечает; зафиксировано тестом «ссылка-приглашение: aria-label на <p>».
3. Для незнакомого `code` показывается `message` сервера (на «вы») — по задумке карточки; сервер по контракту не
   кладёт туда initData, тест «незнакомый код при входе — показывается message сервера как текст».
4. В рабочем дереве есть чужие незакоммиченные правки (`backend/…`, `docs/BACKLOG.md`, `docs/DECISIONS.md`) — к A8
   не относятся; A8 добавил только два файла тестов и этот отчёт.
