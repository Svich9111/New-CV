## 3. Остаточные замечания (не дефекты)

- **О-7.** Проверка D2 требует от каждой таблицы хотя бы одной политики, но не сверяет политики с эталоном.
  Добавленная в копию разрешающая политика `USING (true)` для `feelings_app` пройдёт проверку. Из копии такая
  политика попадёт в базу только если она была в источнике, то есть база уже была ослаблена. Это за пределами
  проверки восстановления. Можно сверять отпечаток `pg_policies` с эталоном ревизии — BACKLOG.
- **О-8.** Прямые права на таблицы у групповых ролей (`feelings_worker`, `feelings_admin`) не проверяются:
  проверка смотрит только роли входа и PUBLIC. Политики RLS выданы `feelings_app`, поэтому такие права без
  политики строк не открывают.
- **О-9.** D3 закрыт настройкой перезапуска. Сами воркеры по-прежнему не отличают недоступность OpenRouter от
  ошибки настройки: постоянная ошибка выглядит как бесконечный `Restarting`. Так и задумано, это описано в
  DEPLOY §4; разделение по коду выхода предложено A3.
- Локальный `infra/docker-compose.yml` остаётся на `on-failure:5`, что описано в ADMIN §4. Для разработки это
  допустимо, находка D3 относилась к стенду.
