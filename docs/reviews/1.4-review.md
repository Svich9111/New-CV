## 2. Безопасность вебхука — проверено

- Секрет проверяется до чтения тела: заголовок берётся через `Header` до `await request.body()`
  (`webhook.py:60` раньше `:66`). Тест `test_secret_checked_before_body_is_parsed` это действительно
  доказывает: если бы JSON разбирался первым, при битом теле вернулось бы 200, а не 401.
- Сравнение — `hmac.compare_digest` над байтами. Утекает только длина, это допустимо.
- Пустой секрет: 503 и для `{}`, и для `""`, совпадения с пустым заголовком нет. В продуктиве
  до этой ветки дело не дойдёт: `check_bot_config` требует 32–256 символов `[A-Za-z0-9_-]`, это
  совпадает с правилами Telegram для `secret_token`.
- Ответы 401/403/503 — статические `{code, message}`. Ни присланный заголовок, ни тело, ни
  конфигурацию они не повторяют. Различие 401 и 403 требует карточка, раскрывает оно только то, что
  ожидается заголовок, и это публичное поведение Telegram.
- После аутентификации тело читается целиком без ограничения размера. Его присылает только Telegram,
  так что риск приемлем.

## 3. Токен бота — проверено

- URL с токеном собирается внутри `_call_once`. В `repr`/`vars` клиента токена нет, поле —
  `SecretStr`.
- Ошибки — только `BotApiError(method, "error_code N")` с `from None`, описание от Telegram не
  включается. Тест покрывает 400/401/500/битый JSON/ConnectError/ReadTimeout, в которых токен
  подставлен в текст исключения.
- Строка httpx `HTTP Request: POST <URL>` проходит фильтр, `_redact_arg` приводит к строке и
  `httpx.URL`. Это подтверждено тестом с уровнем DEBUG (`httpcore` на DEBUG URL не пишет).
- Регулярка `\d{3,}:[A-Za-z0-9_-]{8,}` IP:порт в журнале доступа uvicorn не задевает.

## 4. Замечания

- [MINOR] m1 `backend/app/bot/webhook.py:80-84` + `backend/app/bot/client.py:90-93` — при
  `ReadTimeout`/обрыве после отправки запроса Telegram мог уже доставить сообщение. Отметка всё
  равно снимается, повторная доставка вебхука отправляет `sendMessage` ещё раз, и пользователь
  получает второй ответ. Это видно в `test_timeout_is_transient`: вызовов Bot API там 2. Докстрока
  `client.py:9-11` говорит, что тайм-аут не повторяют, «чтобы не продублировать», но на уровне
  вебхука дубль всё равно возможен. Для ответа на `/start` это безвредно и разрешено карточкой
  («429/5xx/сеть — 503 и снятие отметки»). — Ожидание: написать в докстроке честно: «at-least-once,
  возможен дубль при тайм-ауте чтения». В карточку 3.5 добавить требование: уведомления о сообщениях
  (ФТ-18) не наследуют эту семантику, нужна запись об отправке до вызова или отказ от повтора
  при `ReadTimeout`.
- [MINOR] m2 `backend/app/bot/webhook.py:74-84` — гонка «потерянное обновление». Пусть первая
  доставка долго висит: повторы 429 до 2×10 с плюс тайм-ауты до 3×(5+10) с. Telegram не дожидается
  ответа и шлёт обновление повторно. Повтор видит отметку и получает 200, Telegram считает обновление
  доставленным. Потом первая доставка ловит временный сбой, снимает отметку и отвечает 503 в уже
  закрытое соединение. Ответа пользователь не получит, повторной доставки не будет. Последствие
  малое: пользователь повторит `/start`. — Ожидание: ограничить общее время обработки в вебхуке
  (например, `max_retry_after` для пути вебхука 2–3 с или общий дедлайн) либо записать допущение
  рядом с Б-26. Тест на одновременную повторную доставку пригодится при переносе в Redis.
- [MINOR] m3 `backend/app/core/logging.py:30-37` — фильтр чистит `msg` и `args`, но не
  `exc_info`/`exc_text`. Трассировка с URL Bot API из исключения, которое не перехвачено
  (`setup.py` при неожиданной ошибке, будущие фоновые задачи 3.5), в журнал попадёт как есть.
  Кроме того, локальная `url` в `client.py:87` содержит токен: монитор ошибок с захватом локальных
  переменных (Sentry по умолчанию, ТЗ §10 «мониторинг ошибок») увидит его в кадре `_call_once`.
  — Ожидание: в задаче мониторинга (0.8/4.7) включить очистку кадров и/или отказаться от захвата
  локальных переменных. По желанию — чистить `record.exc_text` в фильтре. Хотя бы строкой
  в BACKLOG.
- [MINOR] m4 `backend/app/bot/client.py:75-84`, `webhook.py:81-84` — при 429 с

## 6. Соответствие Telegram Bot API

- Кнопка `inline_keyboard` → `{"text", "web_app": {"url"}}` работает в личном чате, а бот отвечает
  только в `type == "private"`. Всё согласовано.
- `setChatMenuButton` без `chat_id` с `{"type": "web_app", "text", "web_app": {"url"}}` задаёт
  кнопку по умолчанию. `setMyCommands`, `setWebhook` с `secret_token` и `allowed_updates` заданы
  верно.
- Команды распознаются с `@имя_бота`, в любом регистре и с payload через пробел или перевод строки.
- `setup.py` сам ничего не делает: запускает его только оператор вручную, на импорте и старте
  сервера он не выполняется. Вебхук регистрируется только с явным `--webhook-url` по https и при
  наличии секрета.
