## 2. Ответы на особые вопросы

- **Безопасность разбора.**
  - Ничего не исполняется: pypdf только извлекает текст.
  - XML читается через defusedxml. Сущности и внешние ссылки запрещены, DTD без сущностей пропускается (это
    безопасно). Тест с «миллиардом смехов» есть.
  - XHTML EPUB разбирает `html.parser`: он раскрывает только встроенные именованные ссылки, внешних сущностей нет.
    `script`/`style`/`head` пропускаются.
  - Защита ZIP: число файлов, сумма размеров по заголовкам, степень сжатия файла, фактически прочитанный объём;
    шифрование → `encrypted`. Ложные заголовки ничего не дают: `zipfile` не читает больше заявленного
    `file_size`.
  - Отдельный процесс (`spawn`) с `RLIMIT_AS` 1 ГиБ и убийством по тайм-ауту 60 с; падение → `corrupt`. Для
    недоверенных файлов это достаточно. На macOS `RLIMIT_AS` не действует, но продуктив — Linux.
- **Права 0011.**
  - `feelings_admin`: на `kb_documents` только SELECT колонок без исходника и аренды; запись — `admin_kb_upload`/
    `admin_kb_delete` (с аудитом); на `kb_chunks` нет INSERT/UPDATE/DELETE. SELECT фрагментов есть — это
    справочные данные, не личные.
  - `feelings_worker`: только функции по токену аренды, SELECT `kb_chunks` без векторов.
  - `feelings_app`: SELECT документов без исходника; поиск — `app_kb_nearest` (только `indexed`).
- **Вход администратора.** В конфигурации только SHA-256 токенов, сравнение `compare_digest` со всеми без раннего
  выхода, ротация через несколько хешей. 401 — нет токена или он неизвестен, 403 — действующая сессия Mini App.
  Отдельное подключение (`admin_sessionmaker`, Б-75), `check_admin_config` не даёт задать токены без него. Тело
  формы читается только после проверки входа. Хеш без соли допустим лишь для случайного токена — MINOR-5.
- **Предел тела.** Объявленный `Content-Length` больше предела → 413 сразу; без него байты считаются, на
  превышении приложение получает `http.disconnect`, клиент — 413. Путь загрузки — свой предел (20 МиБ + 1 МиБ).
  Неавторизованная загрузка тело не читает.
- **Запрет цитирования.**
  - Правило: 10 нормализованных слов подряд, совпадающих с фрагментом **этого** контекста, — цитата. Нормализация
    по словам совпадает с индексом (АР-36: дефис, «ё», регистр), разрыв слова между кусками учтён (`tail_open`).
    Придержка k−1 = 9 последних слов гарантирует, что ни один показанный кусок не начинает цитату. Окно из
    10 слов, целиком лежащее в показанном, было проверено раньше — инвариант верен.
  - При совпадении показанное остаётся, хвост заменяется `SAFE_TAIL`: итог — продолжение показанного, заменять
    уже показанный текст не нужно (АР-30). В кризисе от агента в протокол идёт `guard.shown`; кризис от
    классификатора — фиксированные блоки, к ним проверка не нужна.
  - Для §6.4 этого достаточно в связке с запретом в промпте. Дословная цитата в одно предложение и длиннее
    перехватывается кодом. Перефразировка, цитата короче 10 слов и «склейка» с заменой каждого десятого слова не
    ловятся — это ограничение схемы, его надо записать в АР-39 (MINOR-6) и проверить прогоном `l1-07`/`l2-08` на
    настоящей модели.
- **Поиск и порог 0.85.** Порог подобран на заглушке и для настоящей модели должен быть настроен заново (это
  указано в коде, Б-66). Добор до 3 — только при фильтре уровня. Если подходящих меньше трёх, возвращается меньше:
  «по теме» важнее числа — верно.
- **Длинная транзакция индексации.** Разбор, метки и векторы идут вне транзакций; запись фрагментов, векторов и
  завершение — одна транзакция по токену с `FOR NO KEY UPDATE` документа: удаление администратором подождёт
  секунды. Аренда в процессе работы не продлевается — MINOR-3.

## 3. Замечания

BLOCKER и MAJOR нет.

- [MINOR-1] backend/app/api/admin_kb.py:197-204 (`_is_text`) — при загрузке TXT принимается только UTF-8, а
  разборщик и карточка поддерживают CP1251 (`parse_txt`, тест «TXT UTF-8/CP1251»). Файл в CP1251 через API получит
  415, до воркера не дойдёт. Ожидание: та же проверка, что в `parse_txt` (UTF-8, затем CP1251 с проверкой
  управляющих символов), и тест API.
- [MINOR-2] backend/app/ai/dialog.py:329-378 (`draft`) — черновик сообщения партнёру строится с тем же входом
  (`context_payload`, включая `knowledge`), но проверку цитат не проходит (`without_quotes` применяется только к
  `reply`). Черновик показывается автору и уходит партнёру. Сейчас путь из API недостижим (3.1 не сделана,
  `suggest_draft` — только флаг), но в карточку 3.1 нужно: проверка цитат для черновика или черновик без блока
  `knowledge`.
- [MINOR-3] backend/app/workers/kb.py:101-138 + 0011 `kb_claim_index` — аренда 30 мин не продлевается. Метки идут
  последовательно по 8 фрагментов на вызов модели, при пределе 5000 фрагментов это до ~625 вызовов. Для большой
  книги работа может пережить аренду: вторая копия воркера захватит материал снова, удалит фрагменты прежней
  попытки и повторит дорогую разметку. Первая копия на записи получит `lost`, и так до `attempts_exhausted`. С
  одной копией запись проходит (истёкшую аренду проверяет только захват). Ожидание: продление аренды между пачками
  (функция `kb_extend_lease` по токену) или аренда по объёму; тест «работа дольше аренды при двух копиях».
- [MINOR-4] backend/app/api/chat.py:393 (`knowledge=rt.knowledge`) и `workers/kb.py:172` (`embedder=None`) — в
  продукте база знаний не работает целиком: воркер пишет фрагменты без векторов, а `ChatRuntime.knowledge` = None.
  По ограничениям карточки (Б-66, кредиты) это ожидаемо, но критерий «3–5 фрагментов по теме» подтверждён только
  на заглушке. В Б-66 добавить: создавать `DbKnowledgeBase` на запрос в `_prepare` (`user_id`, модель эмбеддера,
  уровень из прошлого ответа), заново подобрать `KB_MAX_DISTANCE`, пересчитать векторы существующих фрагментов.
- [MINOR-5] backend/app/config.py (`admin_token_hashes`) — SHA-256 без соли безопасен только для случайного токена
  высокой энтропии. В `.env.example`/инструкции администратора записать требование (не короче 32 случайных байт,
  команда генерации) и порядок ротации (добавить новый хеш → сменить токен → убрать старый).
- [MINOR-6] docs/DECISIONS.md (АР-39) — зафиксировать границы запрета цитирования: ловится дословное совпадение от
  10 нормализованных слов с фрагментами текущего контекста; не ловятся перефразировка, короткие цитаты и текст
  книги из памяти модели (не из контекста). Прогон `l1-07`/`l2-08` на настоящей модели — условие Г3.

## 4. Тесты

Тесты проверяют критерии фактом:
- четыре формата и все коды отказа, в том числе DTD/сущности, zip-бомбы по трём признакам, зашифрованный PDF,
  тайм-аут и падение отдельного процесса;
- нормализация и разбиение;
- метки и откат на пустые;
- воркер: догон, чужая аренда, две копии, исходник стёрт, журнал без текстов;
- поиск по трём выдуманным темам с фильтром уровня;
- запрет цитирования при любой нарезке потока, в кризисе и в `dialog.reply`;
- права 0011 под ролями;
- админ-API: 401/403, 413 при `Content-Length` и chunked, 415, 409, 422, аудит.

Ослаблений и пропусков нет. Недостаёт:
- TXT в CP1251 через API (MINOR-1);
- работы дольше аренды при двух копиях (MINOR-3).
