## 3. Замечания

**[MAJOR-1]** `frontend/src/admin/adminBuild.test.ts:25` (`src.startsWith("_")`), `:71`; то же в
`frontend/src/admin/boundary.a8.test.ts` (сборка). Общий чанк Vite без своего `src` (`_app-….js`, `_chat-….js`)
проходит проверку модулей целиком, а проверяется только его содержимое на строки-пути. Модуль Mini App без строк-путей
(`src/api/chat.ts`: разбор потока чата, типы `ChatMessage`; `src/api/couple.ts`; `src/ui/format.ts`) подключается в
панель через переэкспорт. Rollup кладёт его в общий с Mini App чанк, и все три стража остаются зелёными. Проверено
мутациями (все стражи зелёные, в манифесте `admin.html → imports: ["_chat-….js"]`, в чанке лежит код `chat.ts`):
- m10: в `src/ui/Notice.tsx` добавлена строка `export { SseParser, parseEvent } from "../api/chat";`, а в
  `src/admin/main.tsx` — `import { parseEvent } from "../ui/Notice"`. Обе правки в `.ts/.tsx`, разрешённый импорт.
- m11: то же через ленивый `import("../ui/Notice")`.
- m6: `src/admin/zzz.js` с `export { SseParser } from "../api/chat.ts"`.

Это ровно сценарий «импорт через переэкспорт другого модуля Mini App», который ревью р.1 просило закрыть. Утверждение
карточки «модули только `src/admin/`, `src/ui/Notice.tsx`, стили, React» не выполняется. Ожидание (карточка 2.8, п.2;
ТЗ §9.1 п.5; АР-52):
(а) проверять состав модулей каждого чанка, а не ключ манифеста. Например, взять `RollupOutput` из `build()`
(`write: false` или плагин `generateBundle`) и `chunk.moduleIds` / `Object.keys(chunk.modules)` для всех чанков,
достижимых от входа `admin`, и требовать, чтобы каждый модуль попадал в перечень разрешённого. Исключение для `_…`
убрать;
(б) в `boundary.test.ts` проверять и разрешённые модули вне `src/admin` (`../ui/Notice`), или отдельно проверить,
что `src/ui/Notice.tsx` импортирует только `react`.

**[MAJOR-2]** `frontend/src/admin/boundary.test.ts:28` (и `boundary.a8.test.ts:25`): `files()` берёт только
`.ts/.tsx`. Файл `.js/.jsx/.mjs` в `src/admin/` не разбирается, а Vite его собирает. Мутация m9:
`src/admin/zzz.js` с `fetch(["", "api", "v1", "chat", "messages"].join("/"))`, подключённый из `main.tsx`. Все три
стража зелёные, вызов есть в `admin-….js`. Вместе с m6 это обход и разбора исходников, и состава модулей. Ожидание:
стражу разбирать все файлы каталога (`ScriptKind.JS/JSX`) или падать на любом файле `src/admin/**` с расширением,
отличным от `.ts/.tsx/.css`. Правка простая и закрывает целый класс обходов (карточка 2.8, п.2).

**[MINOR-1]** `frontend/src/admin/boundary.test.ts:89, 150-154`: запрет `fetch` срабатывает только на прямом вызове
`fetch(…)`, `x.fetch(…)` или `x["fetch"](…)`. Обходы, при которых все три стража зелёные и код есть в бандле:
- m1: `const f = fetch; f(["", "api", "v1", "chat", "messages"].join("/"))`;
- m8: `Reflect.apply(Reflect.get(globalThis, "fetch"), globalThis, [["","api","v1","memory"].join("/")])`;
- m3: `Reflect.get(globalThis, ["local","Storage"].join(""))`, хранилище в обход запрета.

Сборка не видит путь, собранный через `join`. Полного статического запрета не бывает, но три дешёвых правила
закрывают эти обходы. Ожидание:
- любое упоминание идентификатора `fetch` вне `api.ts`, а не только вызов;
- `Reflect`, `Function` (конструктор), строковые `setTimeout`/`setInterval` — в `FORBIDDEN_IDENTIFIERS`;
- `globalThis`/`window`/`self` как значение (присваивание, аргумент), а не только `window[…]`.

Сама защита от запроса к чужим путям во время работы есть: `AdminApi.adminPath` (`api.ts:62-67`). Без двух MAJOR выше
это было бы допустимым остаточным риском.

**[MINOR-2]** `frontend/src/admin/api.ts:15`: `MAX_FIELD_BYTES` клиента тестом не привязан к серверу.
`serverParity.a8.test.ts:167` проверяет только серверное `64 * 1024`, а `KbScreen.test.tsx:308-314` строит границу от
той же клиентской константы, то есть проверяет константу саму собой. Ожидание: в `serverParity` сравнить
`MAX_FIELD_BYTES` из `./api` с `65536`, как это уже сделано для `MAX_FILE_BYTES`.

Мелочь без отдельного замечания: в `boundary.test.ts:39` `@testing-library/*` разрешены и коду панели, не только
тестам. Сборка это перекрывает (модули `node_modules` вне React не пройдут), но перечень для кода лучше сузить.
