### Строгие проверки и корректные ответы контракта

Проверки сверены с `api/openapi.yaml`: `Session`, `Me`, `Couple` и элемент `members`, `InviteCreated`,
`InvitePreview`, `HelpContact`. Каждое проверяемое поле обязательно или имеет нужный тип по контракту.
Необязательные поля (`name`, `address_form`, `partner_name`, `timezone`, `members[].name`, `round_the_clock`)
проверяются через `opt` и в ответе могут отсутствовать. `members: []`, `dissolved`, `inviter_name: null`, 201 на
`POST /couple` и `/couple/invite` проходят, это закреплено позитивными тестами `client.r3`.

Два места строже буквы контракта, но по смыслу допустимы:
- пустой `access_token` с ним нельзя работать;
- `phone` без цифр нельзя набрать.

Поля `expires_in` и формат `uuid`/`date-time` не проверяются. Экраны 1.5 их не читают, ответы это не отбрасывает.

## 4. Отдельные вопросы

- **Объединение «Входим…» и сессии в `Session`.** До входа и после разметка устроена одинаково:
  `AppContext.Provider` → `Frame` на одном месте дерева. Поэтому `BackButton` и ссылка «Помощь» сохраняются,
  и это нужно стражу D6.
  - `setMe`/`setStack` вызываются в отрисовке при `boot.ready && me === null`. Это допустимый в React приём
    «состояние из свойства», он срабатывает один раз.
  - Перезапуск меняет `Fragment key`, `Session` монтируется заново с пустым состоянием, черновик и стек
    сбрасываются.
  - Повторный вход по 401 внутри сессии `boot` не трогает.
  - `AuthError`, «Помощь до входа» при повисшем входе и `Retry` работают как раньше, тесты зелёные.
  - Одна неисправленная особенность прежнего кода стала заметнее — n-6.
- **`boot.tsx` и признак запуска по адресу.** Злоупотребить им нельзя. `launchedFromTelegram` влияет только на
  проп `sdk` экрана `Outside`: «Загружаем…» или «Не получилось связаться с Telegram» вместо «Открой в Telegram».
  - `tg.inside` по-прежнему определяется только `findWebApp`: загруженный SDK и непустой `initData`. Без них
    вход не вызывается, сессии и данных нет. Публичным остаётся только `GET /help/contacts`.
  - Строка `tgWebAppData` клиентом не читается и не передаётся.
  - Если вне Telegram подставить `#tgWebAppData=…`, а настоящий SDK загрузится, он разберёт строку в `initData`,
    и вход уйдёт на сервер с поддельной подписью. Сервер её отклонит (ФТ-01, проверка HMAC). Так было и до этого
    раунда, нового пути атаки нет.
  - `TelegramUnavailable` → `location.reload()`: безопасно.
- **`public/sdk-state.js` по корневому пути.** Сейчас это верно: `base` в `vite.config.ts` не задан, файл
  копируется в корень `dist`. Если скрипт не загрузится (другой `base`, 404, блокировка), ломается ветка «SDK упал
  после срока» — см. n-7. Остальное работает: `waitForTelegramSdk` слушает сам скрипт, поздний `load` даёт
  `Telegram.WebApp`.
- **`LastResort` статичен.** Внутри только `div`, `h1`, `p role=alert`, `a href="tel:112"` и кнопка в странице.
  SDK, контекстов, запросов и `MainButton` нет. При «Перезапустить» его состояние сбрасывается: `Boundary`
  размонтирует его, когда снова рисует детей.
- **Безопасность и CLAUDE.md.**
  - В новом коде нет `console`, хранилищ браузера, `innerHTML` и `eval`. `new Function` есть только в
    `indexHtml.test.ts`, он исполняет свой файл.
  - `tel:` строится из отфильтрованного номера.
  - Контракт не менялся, сгенерированные типы свежие.
  - Слой доступа и промпты задача не затрагивает. Данные в тестах выдуманные.

### MINOR

- **[MINOR] n-6 `frontend/src/app/App.tsx:185-188, 242-262` — «Помощь», открытая на «Входим…», закрывается
  сама, когда вход завершается.**
  - Флаг `helpBeforeLogin` учитывается только пока `state` нет. Когда вход завершается, первым экраном становится
    `initialRoute`, и человек, который читал номера помощи, оказывается на «Твой личный агент» без «Назад»
    (зонд 2).
  - При ошибке входа «Помощь» остаётся (тест A8 «вход повис»), при успехе — нет. Так было и в р.2, это не
    регрессия.
  - Ожидание: при `helpBeforeLogin` ставить стек `[initialRoute(...), { name: "help" }]`, чтобы «Назад» вела на
    первый экран. Нужен тест «Помощь до входа → вход успешен → «Помощь» на месте, «Назад» → первый экран».
  - Основание: ТЗ §9.3 («Помощь» доступна всегда), карточка («Помощь» с каждого экрана). Можно закрыть в бэклоге
    до Г1.
- **[MINOR] n-7 `frontend/src/telegram/webapp.ts:131-151`, `frontend/src/boot.tsx:472-485` — ветка «SDK упал после
  срока» зависит от `sdk-state.js`.**
  - `onSdkScriptSettled` не передаёт, какое событие пришло. `mount()` снова читает `data-state`. Если
    `sdk-state.js` не выполнился (выкладка не в корень домена, 404, блокировка), после `error` состояние остаётся
    `pending`, экран снова «Загружаем…».
  - Подписки больше нет: подписка ставится только по результату первого `mount()`. Человек в Telegram ждёт
    бесконечно, без «Попробовать снова» (у него остаётся «Помощь»).
  - Ожидание: передавать в `cb` тип события (`load`/`error`) и выбирать экран по нему, а не только по
    `data-state`. Либо держать в карточке явный пункт проверки «путь `sdk-state.js` при выкладке» перед Г2. Сейчас
    там только примечание A4.
  - Основание: n-2, n-3 р.2; ТЗ §8.

Наблюдение без замечания: в заметке A4 указано «18 файлов, 410 тестов», это совпадает с прогоном ревьювера.
