## 3. Дефекты

- [MINOR] **A8-0.8-D1** — `docs/DEPLOY.md` не учитывает сервис `worker-pipeline`, добавленный в 6bc39d0.
  - §6 (обновление): `dc stop api worker-memory worker-kb`.
  - §10 (восстановление на том же сервере): `dc stop caddy api worker-memory worker-kb`.
  - §4: комментарий `dc up -d # caddy, api, worker-memory, worker-kb`.

  Последствие: при восстановлении `worker-pipeline` продолжает работать. `DROP DATABASE … WITH (FORCE)` обрывает его
  подключение, и между `db-init`, `pg_restore` и `restore-check` он снова подключается к базе и вызывает функции
  захвата. При обновлении он работает во время миграций. Нужно добавить `worker-pipeline` во все три места.

- [MINOR] **A8-0.8-D2** — `restore-check.sh` проверяет RLS только как «хотя бы у одной таблицы включён RLS». Он не
  сравнивает права таблиц с ожидаемыми. Копия, где у `users` выключен RLS или удалены политики, или где у роли входа
  `feelings_api` есть прямое `SELECT ON users`, проходит проверку («восстановление проверено»). Также проходит
  `--db feelings` после восстановления. Тест `test_restore_check_detects_rls_and_grant_weakening[3]` (xfail strict).
  Предложение: сверять список таблиц с RLS и FORCE RLS и число политик с эталоном схемы (например, все таблицы
  `public`, кроме `alembic_version`) и требовать, чтобы у ролей входа (`feelings_api`, `*_login`) не было прямых прав
  на объекты.

- [MINOR] **A8-0.8-D3** — у worker-memory и worker-pipeline `restart: "on-failure:5"`, а временную недоступность
  OpenRouter при старте (`fetch_price` → `LLMUnavailable`) они не отличают от ошибки настройки. На стеке оба
  контейнера после 5 быстрых перезапусков остались `exited` (`restarts=5`). После короткого сбоя сети или DNS при
  загрузке сервера конвейер входящего и память остановятся до ручного `dc up`: отправленные сообщения останутся
  «в обработке». ADMIN.md §4 описывает это только для отсутствующего ключа. Предложение: при `unavailable` на старте
  повторять внутри процесса или различать коды выхода. До 4.7 — хотя бы описать в DEPLOY §4/§6 проверку `dc ps`
  после выкладки и перезагрузки.

## 5. Наблюдения (не дефекты)

- О-1. Порты Caddy публикуются на всех адресах (`0.0.0.0:80/443`), как положено серверу. Для локальной проверки DEPLOY
  §11 стоит добавить переопределение `ports: !override ["127.0.0.1:…:443"]`: без него проверка занимает 80/443
  машины разработчика.
- О-2. `backup.sh` и `restore-check.sh` берут имя проекта из `name: feelings` compose-файла. Для локальной проверки
  под другим именем нужен `COMPOSE_PROJECT_NAME` — в DEPLOY §11 это не сказано.
- О-3. `FEELINGS_ENV=production` точка входа пропускает. Это задумано для 4.7, на стенде запрет держится только на
  DEPLOY §12.
