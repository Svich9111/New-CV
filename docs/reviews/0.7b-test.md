## 5. Дефекты

- [MAJOR] D-1 (= BACKLOG Б-13, срок — задача 1.3). У `feelings_app` остались прямые
  `UPDATE couple_members(active, left_at)` и `UPDATE couples(status, dissolved_at)`. Факт: партнёр
  прямым UPDATE выходит — пара остаётся `active` с одним участником, инициатор «заперт» (новая пара —
  23505, чужая ссылка — FB005); активный участник прямым UPDATE ставит `dissolved` — оба остаются
  `active`. Нарушает инвариант §4.5 п.2 / АР-13 «выход распускает пару для обоих». Тесты:
  `test_b13_direct_member_leave_denied`, `test_b13_direct_dissolve_denied` (xfail strict).
  Для 0.7b не блокирует: зафиксировано в BACKLOG с планом отзыва прав в 1.3; `app_leave_couple`
  восстанавливает согласованность (`test_leave_recovers_inconsistent_couple`).
- [MINOR] D-2. `app_accept_invite` не проверяет длину хеша (в `app_issue_invite` — 22023): хеш не
  32 байта даёт FB001. На безопасность не влияет; несогласованность кодов между функциями.
- [MINOR] D-3. Поддельный/удалённый `app.user_id` в `app_accept_invite` даёт ошибку FK (23503), а не
  42501: функция не проверяет, что пользователь существует (`PERFORM … users` без `IF NOT FOUND`).
  Через API недостижимо (идентификатор из проверенной сессии); вступления нет.
