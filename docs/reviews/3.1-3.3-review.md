### Замечания 3.1

- [MINOR-1] backend/app/ai/drafts.py:120-128 — если вторая линия не дала вердикта (ошибка или отказ
  классификатора), черновик всё равно создаётся. Для чата в таком случае по АР-34 к ошибке добавляется подсказка
  помощи, а здесь владелец получает обычный черновик без указания на помощь. До партнёра черновик не дойдёт без
  проверки конвейера (3.2: безопасность до доставки, сейчас сообщение остаётся в `processing`), поэтому риск
  невелик. Ожидание: при `screen.verdict is None` — подсказка помощи в ответе (поле или заголовок по контракту, A1)
  или явная запись в АР-40, что вторая линия черновика допускает пропуск.
- [MINOR-2] backend/app/api/drafts.py:124-129 + `repositories/drafts.send` — нерасшифрованный черновик в `GET`
  отдаётся как 404, но `send` его принимает: `app_send_draft` копирует байты, и партнёр получит нечитаемое
  сообщение (у автора в ответе 202 — `UnavailableText`). Ожидание: в `send` при `reason is not None` — отказ (409
  `not_editable` или отдельный код через A1) до вызова функции.
- [MINOR-3] backend/app/ai/drafts.py (`_generate`) — длина текста черновика от модели не ограничена, а `PATCH`
  принимает ≤ 4000 символов. Длинный вариант модели автор не сможет сохранить после правки. Ожидание: тот же
  предел 4000 при генерации (повтор с пожеланием «короче», затем ошибка).
- [MINOR-4] Б-77 — проверка цитат черновика сейчас работает вхолостую: в API `ChatRuntime.knowledge = None`
  (Б-66), индекс фрагментов пуст. Это ожидаемо; при подключении базы знаний тест API на `draft_quote` с
  настоящим `DbKnowledgeBase`.
