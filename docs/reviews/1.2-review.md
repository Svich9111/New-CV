## 2. Замечания

- [MAJOR] `api/openapi.yaml:107-112`, `api/openapi.yaml:654` (MAJOR-1). У `PUT /me/onboarding` объявлены только 200, 403 и 422. Сервер отдаёт **401** без сессии, с неверным токеном и удалённому пользователю (`auth.py:58-63`, `deps.py:32-41`), и это закреплено тестами `test_onboarding.py:297, 304`. У `GET /me` 401 объявлен. У ответа 403 нет примера `{code: underage}`: код появился только в общем списке `Error.code.examples`. Этот список правил A2, хотя по CLAUDE.md и `.claude/agents/a2-backend.md:10` контракт меняет только A1. Та же ситуация была в 1.1 (MAJOR-3). Ожидается: A1 через карточку добавляет `"401": { $ref: "#/components/responses/Unauthorized" }` и пример `underage` у 403 (или выделенный `responses/Underage`) и подтверждает правку `examples`. Плюс тест вида `test_every_onboarding_status_is_declared_in_contract`: полученные коды {200, 401, 403, 422} входят в объявленные. (CLAUDE.md «Контракт API меняет только A1»; карточка «по контракту».)
- [MAJOR] `backend/app/schemas.py:66, 72-74` (MAJOR-2). Согласие как `Literal[True]` в режиме `strict=True` всё равно принимает `1` и `1.0`. Проба через API: `consent_terms: 1` → 200, `consent_data: 1.0` → 200, согласие записано. При этом `age_confirmed: 1` → 422, то есть поля ведут себя по-разному. Контракт требует `type: boolean, const: true`, а согласия юридически значимы (§9.4). Ожидается: строго булево `true`, например `Annotated[StrictBool, AfterValidator(_must_be_true)]`, и параметры `1`, `1.0`, `"true"` в `test_missing_consent_is_422_and_nothing_saved`. (Карточка, критерий 1; контракт `OnboardingRequest`.)
- [MINOR] `backend/app/schemas.py:32` (MINOR-3). `_CONTROL` ловит только C0 и DEL. Проходят `U+0085` (NEL), `U+2028` (разделитель строк), `U+202E` (смена направления текста) и строка из одного `U+200B` (пустое имя, не обрезается `strip`). Ожидается: отклонять категории Unicode `Cc`/`Cf`/`Zl`/`Zp` (`unicodedata.category`) и проверять, что после удаления невидимых символов строка не пустая. Тесты на эти символы. (Карточка, критерий 5.)
- [MINOR] `backend/app/schemas.py:43-45` (MINOR-4). `zoneinfo.available_timezones()` объединяет системный `TZPATH` с пакетом `tzdata`, поэтому набор допустимых зон зависит от хоста (в образе без `/usr/share/zoneinfo` и на машине разработчика он разный, а `right/…` и `posix/…` могут попасть в набор). Ожидается: брать список только из `tzdata` (`importlib.resources.files("tzdata").joinpath("zones")`) или фиксировать `TZPATH=()`, чтобы результат был одинаковым везде. Устаревшие ссылки (`EST`, `W-SU`, `US/Eastern`) допустимы.
- [MINOR] `backend/app/repositories/users.py:80-95` (MINOR-5). Каждый `PUT` с `age_confirmed=false` добавляет новую строку `safety_events`: проба — 5 запросов дали 5 событий. Ожидается: не писать повторное событие, пока `age_confirmed_at IS NULL` и событие уже есть (или ограничить частоту в 2.x/Б). Можно перенести в бэклог.
- [MINOR] `backend/app/repositories/users.py:31-42` и `users.py:98-` (MINOR-6). Условие «онбординг завершён» записано дважды (`is_onboarded` и `get_me.onboarded`). - [MINOR] `backend/tests/test_onboarding.py:179-193` (MINOR-7). ## 3. Рекомендации по вопросам исполнителя (Заметки A2)

1. **Порядок «схема → возраст» (запрос без согласий и с `age_confirmed=false` получает 422, событие не пишется).** Оставить. Доступ в обоих случаях закрыт, контракт описывает 422 как ошибку данных. Экран 1.5 не должен давать отправить форму без согласий, поэтому на практике `false` придёт вместе с согласиями. Записать поведение в карточку 1.5 для A4.
2. **`false` у уже прошедшего онбординг снимает `age_confirmed_at`.** Принять: это прямое следствие §9.3. Вместе с АР-14 оператору стоит решить, удалять ли накопленные данные (агент, память) у пользователя, заявившего возраст младше 18. Сейчас они сохраняются, а §9.3 этого не регулирует.
3. **Время согласий фиксируется при первом согласии.** Принять. Когда появятся отзыв согласия и новые редакции документов (4.6), понадобится версия документа. Нужно предложить A1 поле или журнал согласий (`audit_log`) через карточку 4.6.
4. **Обрезка пробелов, отказ на управляющих символах, IANA без служебных файлов.** Принять, но расширить, см. MINOR-3 и MINOR-4.
5. **Правка `Error.code.examples` в контракте.** Правку должен оформить или подтвердить A1, см. MAJOR-1. Тестовый маршрут `probe` только в тестах — правильно, `test_implemented_routes_exist_in_contract` остаётся строгим.
6. **АР-14 (повтор с «да» после «нет» не блокируется).** Реализация соответствует предложению, но решения оператора нет. Задачу можно закрыть только со статусом ⚠️ и ссылкой на АР-14. Если оператор выберет блокировку, понадобится флаг в `users` (миграция, A1) и отдельный код 403.
