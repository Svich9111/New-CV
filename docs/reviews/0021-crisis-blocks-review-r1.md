## Находки

**[MAJOR-1] `backend/app/ai/pipeline.py:105-112` (с `crisis.py` правило «Б», `plan`), `docs/DECISIONS.md:82` (АР-57 п.4),
`docs/BACKLOG.md:109` (Б-103) — Б-103 меняет порядок блоков кризисного ответа, хотя записано «блоки ответа от этого
не меняются».** В правиле «Б» главная строка задаёт блок сразу после экстренного (`sequence += [main, *rest]`).
Ранее при категории модели `self_harm` и вторичных `violence`, `life_threat` главной была `self_harm`; теперь кодом —
`life_threat`, и остальные идут по `PRIORITY`. Проверено перебором всех 32 сочетаний: ровно одно расхождение —
`{violence, self_harm, life_threat}` при категории `self_harm`:
`('not_sent','life_threat','self_harm','violence')` → `('not_sent','life_threat','violence','self_harm')`
(действия те же). Помощь не теряется и ничего не смягчается, но поддержка при самоповреждении уходит после блока
пострадавшему от насилия — это изменение текста кризисного ответа (§9.3), не отражённое в решении и не закреплённое
тестом: `test_b103_life_threat_primary_by_code` проверяет только главную, а в правках чужих тестов комментарий
«блоки от главной не зависят» верен только для правила «А». Ожидание: (а) исправить формулировку в АР-57 п.4 и Б-103
(«в правиле «Б» при трёх и более признаках порядок вторичных — по `PRIORITY`, а не по категории модели») и добавить
тест, фиксирующий новый порядок для этого сочетания; либо (б) сохранить порядок вторичных от категории модели
(например, передавать в `plan` порядок «категория модели, затем PRIORITY» после `life_threat`). Выбор между (а) и (б)
— вопрос 6 карточки 3.4 (психолог, Д5); до решения — хотя бы (а). (ТЗ §9.3; АР-57 п.4; задание раунда: «не изменилось
ли поведение кризисного ответа сверх заявленного».)

## Проверенное без замечаний

  false у `feelings_app/worker/api/admin`; прямой `SELECT` под пользователем — 42501; функция ленты отдаёт набор
  только автору, получатель остановленного не видит вовсе. Клиент дополнительно отбрасывает поле у входящих и при
  причине не `safety`.
- **Нет текстов.** Колонка — массив перечисления; в API — только имена блоков из enum; новых строк журнала нет
  (предупреждение `crisis type unknown` — без данных).
- **Откат клиента.** Неизвестное имя, повтор, пустой массив, не массив, имя из прототипа (`toString` — проверка через
  `Object.hasOwn`) → весь набор отбрасывается, а не одно имя; `isCoupleFeed` при этом не падает, помощь и 112 под
  сообщением есть. `ConservativeBlock` статически исключает блоки пострадавшему и «вернёмся к разговору» из отката.
- **Миграция.** Замена, а не перегрузка (неоднозначности 5/6 арг. нет); 4-арг. обёртка 0014 снята в 0016, её

  `0015–0020` эти функции не переопределяют — опора на тела 0014 верна. Нормализация набора (`DISTINCT … ORDER BY` по
  перечислению) на результат не влияет: `crisis.order` сортирует по `PRIORITY`.
