запуске процесса использует набор промптов `V0`. АР-26 прямо: «Набор `V0` — только для прототипа 0.5; **в 3.2/продукт

`python -m app.workers.pipeline` в любом окружении включил бы непрогнанные промпты на реальных сообщениях
(нарушение правила CLAUDE.md «изменение промпта — … прогон эталонного набора»).
Ожидание: либо запись в `DECISIONS.md` (A0/оператор: V0 допускается в 3.2 до прогона, только на тестовом стенде),
либо закрытая по умолчанию настройка — набор промптов обязателен в окружении (`FEELINGS_PIPELINE_PROMPT_SET`),
без него `_main` не стартует; в тестах `V0` передаётся явно. Комментарий модуля привести в соответствие.

**MAJOR-2** `backend/app/workers/pipeline.py:173–176` — `quota`/`auth`/`config`/`bad_request`/`model_not_found` →
сразу `withheld/pipeline_error`, одобрение израсходовано, автору нужно новое «Отправить». Буквально это следует
АР-27 («ошибки настройки — не доставляется»), но АР-27 решает, *что не доставлять без адаптации*, а не что сообщение
нужно окончательно закрыть. Последствие: при исчерпании кредитов (текущее состояние, см. «Ограничения» карточки),
отозванном ключе или опечатке в id модели **все** сообщения всех пар за время инцидента безвозвратно становятся
«не доставлено», хотя после пополнения/исправления они прошли бы. Это противоречит §10 («отказ модели —
понятное сообщение, черновик не теряется»; черновик уже `sent`, повторно его не отправить) и превращает
эксплуатационный инцидент в потерю сообщений у пользователей. Тест `test_config_error_is_pipeline_error`
закрепляет именно это поведение.
Предложение (нужна запись в `DECISIONS.md`):
- `quota`, `auth`, `config`, `model_not_found` — «сервис не настроен», а не свойство сообщения: не завершать и не
  расходовать попытку; воркер переходит в паузу (circuit breaker: перестаёт захватывать на N минут, пишет ERROR
  без текстов — сигнал мониторингу), сообщение снова в очереди. Для этого A1 — функция
  `pipeline_release(p_message, p_token, p_retry_after interval, p_count_attempt boolean)` (снять аренду досрочно и
  при необходимости вернуть счётчик). Предел ожидания — по возрасту (`sent_at` старше, напр., 24 ч →
  `attempts_exhausted`), чтобы автор не видел «отправляется» бесконечно;
- `bad_request` (ошибка в коде, детерминирована для этого запроса) — оставить `pipeline_error`;
- в любом случае автору в `pipeline_error`/`attempts_exhausted` клиент должен предлагать «отправить снова»
  (новый черновик с тем же текстом) — передать в 3.4.

**MAJOR-3** `backend/app/workers/pipeline.py:180–181`, `0013_pipeline_worker.py:109–110` — при кризисе воркер
выбрасывает `delivery.author_notice`/`delivery.safety_event`, а в строке сообщения остаётся только

## 3. Проверено и замечаний нет

- **Ровно один раз и аренда.** Захват `FOR NO KEY UPDATE OF m SKIP LOCKED`, новый токен на каждый захват;
  чтение и оба завершения — только по своему токену и в `processing`; истёкшая, но не перехваченная аренда
  завершается; старый токен после перехвата → `lost`/`false` без событий; `attempts_exhausted` ставит БД без
  модели; две копии воркера — каждое сообщение один раз (тесты БД и воркера).
- **Порядок блокировок.** `LOCK_LEASED`: автор `FOR KEY SHARE` → пара `FOR KEY SHARE` → сообщение
  `FOR NO KEY UPDATE` → исходное (ответ). Согласован с `app_delete_account` (пользователь → пары → сообщения),
  `app_leave_couple`, `app_send_draft` (`FOR KEY SHARE`). Гоночные тесты в обоих порядках (удаление автора,
  удаление получателя, выход любого, отправка при открытой доставке) — без 40P01/23503. Захват ничего не ждёт.
- **Изоляция.** Во входе моделей — только оригинал (и адаптация для контроля смысла); память, диалоги, имена и id
  обоих партнёров не попадают; системные промпты — неизменные файлы, текст — значение поля JSON.
- **Права.** Все функции 0013 — `SECURITY DEFINER`, `SET search_path = public, pg_temp`, имена с `public.`,
  `REVOKE ALL FROM PUBLIC`, `EXECUTE` только `feelings_worker`; у `feelings_app` нет прав на новые колонки;
  `app_couple_feed_page` пересоздана с теми же правами, причина — только автору.
- **Журналы.** Только статус, причина/вид ошибки (имя класса), попытка, флаг адаптации; ни текстов, ни id.
- **Миграция.** Обратимость 0013 → 0012 → 0013 с заполнением прежних `withheld`/доставленных — тест есть;
  CHECK-ограничения причины и аренды; `tables.py` согласован.
