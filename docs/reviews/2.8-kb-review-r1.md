## Соответствие клиента серверу (`admin_kb.py`)

- `GET /admin/kb/documents` → 200 массив; клиент требует именно 200 и массив, иначе `bad_response`. ✅
- `POST` → 202; поля multipart `file`, `title`, `author`, `approach`, `rights_basis` — совпадают с `UploadFields`
  (`extra="forbid"`: лишних полей клиент не шлёт). Пустые необязательные поля не отправляются — сервер их и так
  превращает в `null`. Коды 409 `duplicate_document`, 413 `file_too_large` (и 413 из `BodyLimit` с тем же кодом, и
  413 Caddy без JSON), 415 `unsupported_format`, 422 `validation_error` — все сопоставлены. ✅
- `DELETE /admin/kb/documents/{id}` → 204; 404 с кодом `not_found` (`errors.NOT_FOUND_CODE`) → `gone`. ✅
- 401 `unauthorized`, 403 `admin_only` — из `admin_access`. ✅
- Строгая проверка `KbDocument` (`api.ts:76-111`) совпадает со схемой контракта: `index_error` `^[a-z][a-z0-9_]{0,31}$`,
  `source_size` 1…20 971 520, `sha256` `^[0-9a-f]{64}$`, перечисления статусов и форматов. ✅
- Не сопоставлены коды, которые сервер реально отдаёт: 500 `internal` (`errors.py`, `_unhandled`) и 409 `conflict_retry`
  (`errors.py`, `_db_conflict`; контракт, строки 13–16 — на любом пути) — MINOR-1.

**[MINOR-1]** `frontend/src/admin/texts.ts:9-26` — реальные коды сервера без своего текста: 500 приходит с JSON
`{code: "internal"}` (`backend/app/errors.py`, `_unhandled`), поэтому ветка `server_error` срабатывает только для
ответа без JSON, а настоящий сбой сервера показывается как «Сервер ответил ошибкой (код «internal»)»; тест
`KbScreen.test.tsx` «ответ 500 internal» закрепляет именно этот запасной текст. 409 `conflict_retry` (АР-24; контракт,
строки 13–16 — на любом пути; для `DELETE` при одновременной индексации вероятен) — тоже запасной текст вместо «Не
получилось с первого раза — повторите». Ожидание: `internal` → «Сбой на сервере…», `conflict_retry` → «повторите»,
тесты на оба кода для загрузки и удаления (карточка: «все коды ответа — понятный текст»).

**[MINOR-2]** `frontend/src/admin/KbScreen.tsx:45, 87, 102` — гонка списка с изменениями: ответ `GET`, ушедшего до
`POST`/`DELETE` и пришедшего после, целиком заменяет `docs` (`setDocs(list)`). Итог — только что загруженный материал
пропадает из списка (и опрос может остановиться, если других `uploaded`/`indexing` нет), а удалённый — возвращается
до следующего «Обновить» (повторное «Удалить» даст «уже был удалён»). Окно короткое, но при опросе каждые 5 с во время
индексации — реальное. Ожидание: номер поколения запроса — ответ списка, начатого до последнего изменения,
отбрасывается (или после 202/204 — повторный `load()` после текущего); тест с `deferred()` на `GET` поверх загрузки и
удаления.

**[MINOR-3]** `frontend/src/admin/api.ts:188, 197-198`, `Login.tsx:16-24` — токен с символом вне Latin-1 (кириллица
при вставке, неразрывный пробел) или с переводом строки внутри: `Headers` бросает `TypeError` (проверено в Node), он
превращается в `network`, и администратор видит «Нет связи с сервером» вместо «Токен не принят». Ожидание: при входе

**[MINOR-4]** `frontend/src/admin/UploadForm.tsx:25-27` — длины проверяются по `String.length` (UTF-16), сервер
