## 2. BLOCKER-1: проверка закрытия

Инвариант после исправления такой. `send`, `regenerate` и `reject` берут id и версию из `memory` экрана. Подтверждение на сервере идёт по `expected_version`. Поэтому сервер примет отправку, только если на сервере сейчас ровно показанная версия; любое другое состояние даёт 409. Пути из задания разобраны по коду и проверены временными тестами там, где это возможно.

## 3. MAJOR-1: таблица блоков против `crisis.respond`

Признаки сообщения: T (`outgoing_threat`), V, H, L в любом сочетании. Главный тип — категория классификатора (`pipeline.py:412`). Код это не проверяет, а `safety.v2.md:54-55` велит ставить L главным. Я перебрал все сочетания для каждого главного типа:

| Главный | Клиент | Блоки, которые сервер (`respond`, `withheld=True`) запрещает, у клиента есть? | Что клиент теряет относительно сервера |
| --- | --- | --- | --- |
| T | `not_sent`, `outgoing_threat_brief`, `author_safety` | нет: «вернёмся к разговору», «подумаем, как сказать», «вина не на тебе» отсутствуют | только T: `return_to_talk` (§9.3 стр. 2). T+H: блок `self_harm` (круглосуточная помощь, «остаюсь в разговоре»). T+L: безусловное «немедленно звони» (`author_safety_life`) |
| V | `not_sent`, `author_safety` | нет | только V: `name_it`, `no_tolerate` (§9.3 стр. 1). V+H: `self_harm`. V+L: «немедленно звони» |
| H | `not_sent`, `self_harm`, `author_safety` | нет: при H+T сервер тоже ставит `self_harm`, а лишний `author_safety` нейтрален | H+L: «немедленно звони» |
| L | `not_sent`, `author_safety_life` | нет: блока `life_threat` («Твоя жизнь сейчас в опасности») нет | L+H: `self_harm`. L+V без T: `name_it` |
| `null` | `not_sent`, `author_safety` | нет | — |

Вывод. Требование раунда 1 выполнено: клиент не показывает блоки, которые правила R2-MAJOR-1/R5-MAJOR-1 запрещают хотя бы при одном сочетании. Во всех строках есть «звони в экстренные службы», `HelpContacts` и 112 (тест `Messages.test.tsx` по каждому типу). По вопросу из задания: при T+H сервер тоже не даёт «немедленно звони», это блок только для L. У клиента при T+H «звони в экстренные службы» есть (условное, в `author_safety`), нет блока `self_harm`. Безусловное «немедленно» (§9.3 стр. 4) теряется только при вторичном L. Классификатор при L должен ставить его главным, так что путь маловероятен, но код этого не гарантирует. Безопасного для всех сочетаний блока, который восстановил бы утраченное, в `crisis.v2` нет. Решение возможно только через контракт (предложение A1 № 5).

## 5. Находки

**[MINOR-A] `docs/tasks/3.4.md` («Заметки A4 (раунд 2)», «Цена»; вопрос 6) — цена консервативного набора описана не полностью (ТЗ §9.3; CLAUDE.md: отступление от ТЗ — только с решением оператора в `DECISIONS.md`).** В карточке названы только потеря `self_harm` при главном V и «расскажи, что тебя задело» при чистом T. Не названы:
- при чистом V не выполняется §9.3 стр. 1 («называет происходящее своим именем», «не призывает терпеть»);
- при чистом T не выполняется стр. 2 («предлагает вернуться к разговору»);
- при вторичном L нет безусловного «немедленно звони» (стр. 4);
- при вторичном H нет блока поддержки с круглосуточной помощью (стр. 3).

Ожидание: дополнить «Цену» и вопрос 6 этим списком. Тогда оператор и психолог (Д5) решают с полной картиной, а A0 не принимает 3.4 как соответствующую §9.3 до ответа на вопрос 6 или до предложения A1 № 5. Код менять не нужно.

**[MINOR-B] `frontend/src/screens/Draft.race.test.tsx` — нет стража на главный инвариант «действия берут черновик из `memory`, а не из сессии».** Мутация `const mine = couple.draft ?? memory` (`Draft.tsx:253`) проходит весь набор. Достижимый сценарий её ловит. Прежний экран ждёт «Другой вариант» (ответ задержан) → «Назад» → «Подготовить ответ» с тем же `replyTo` (на экране v1 из сессии) → вариант приходит (в сессии v2) → «Отправить». С мутацией партнёр получает v2, которого на экране не было. На текущем коде send идёт с v1, сервер отвечает 409, ничего не отправлено. Временный тест в чистой копии подтвердил оба исхода. Ожидание: добавить этот случай в `Draft.race.test.tsx`: отправленное равно показанному, а при расхождении ничего не уходит. Это защитит исправление BLOCKER-1 от регресса (карточка, критерий «`expected_version` = версия на экране»).

Наблюдение вне 3.4, без оценки. В `pipeline_work.crisis_type` при главном `underage` события равны `(underage, underage)`, поэтому тип становится `life_threat` даже при известном вторичном признаке. Клиент тогда показывает «Здесь есть угроза жизни». Для `kind = message` `underage` по промпту не ставится. Решает владелец 3.2.
