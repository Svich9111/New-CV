## Дефекты

- **[MINOR] A8-V1** `backend/app/ai/embeddings.py:96–107` (`check_dim`) и `backend/app/repositories/chat.py:314`
  (`_memory` → `app_memory_nearest` внутри общей транзакции `read_context`) — вектор и модель, которые приложение
  пропускает, а БД отклоняет 22023, роняют всю сборку контекста вместо отката на свежесть: компонента вне диапазона
  float4 (`1e39` — конечна в Python, `check_dim` пропускает; `embedding_arg` → «bad embedding»), имя модели эмбеддера
  длиннее 128 (`Embedder.model` не проверяется; «bad embedding model»). Ошибка в той же транзакции прерывает и чтение
  реплик и пары — в API это `error internal` на каждую реплику, пока эмбеддер отдаёт такие значения. Ожидается (ТЗ
  §6.1 п.3, АР-35, карточка «без эмбеддера — по свежести»): `check_dim` отклоняет значения вне float4 (|x| > 3,4e38),
  длина модели проверяется до запроса (или вызов поиска — в точке сохранения `SAVEPOINT` с откатом на свежесть при
  22023). Нулевой вектор уже обработан (`check_dim`), компоненты 1e-30 — норма не ноль и для БД (проверено).
  Тест: `test_context_db_rejected_vector_falls_back[float32_overflow, long_model_name]` (xfail strict).

## Замечания без дефекта

- **О-1** путь «> 1000 записей» в `app_memory_nearest` — не обязательно HNSW: для агента с 1300 записями среди
  9400 планировщик выбрал перебор по `agent_id` с сортировкой (счётчик сканов HNSW не рос), для агента с 7000 —
  HNSW. В обоих случаях выдача полная, упорядоченная, recall@8 на кластеризованных данных — 1,0. Утверждение
  АР-35 «индекс используется» верно для доминирующего агента; для остальных — решение планировщика (это нормально).
- **О-2** `check_help_contacts_config` и опрос бота различают окружения по-разному (регистр) — без изменений с 2.1 (О-3
  раунда 2), к сведению.
- Модель в БД не нормализуется: `' '` (пробел) — допустимое имя модели (не пустое). Безопасно, к сведению.
