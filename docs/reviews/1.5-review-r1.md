### MAJOR

- **[MAJOR] `frontend/src/telegram/webapp.ts:119-124` и `frontend/src/main.tsx:251-252` — в клиентах Bot API
  6.1–6.8 приложение может не запуститься.** `applyTheme()` вызывает `setHeaderColor("#ffffff")` при
  `isVersionAtLeast("6.1")`. В официальном `telegram-web-app.js` до 6.9 `setHeaderColor` принимает только
  ключи `bg_color` / `secondary_bg_color` (или hex, совпадающий с `themeParams.bg_color`). На любой другой
  hex он пишет `console.error` и бросает `WebAppHeaderColorKeyInvalid`. Наш `--bg` (`#ffffff` / `#000000`)
  почти никогда не совпадает с `themeParams.bg_color`. Исключение вылетает из `tg.start()` на верхнем уровне
  `main.tsx` до `createRoot().render()` и до `wa.ready()`: пустой экран и вечный индикатор загрузки Telegram.
  Обработчик `themeChanged` падает так же. Подделка `fakeTelegram` не бросает, поэтому тестов на версии
  6.1–6.8 нет. Ожидание: для `setHeaderColor` нужна проверка `isVersionAtLeast("6.9")`, а для 6.1–6.8 — ключ
  `bg_color` или пропуск вызова. Кроме того, `start()` должен быть устойчив к исключениям SDK
  (`try/catch`, `ready()` вызывается всегда). Ещё нужен тест с версией `"6.2"`, где подделка бросает
  исключение, как настоящий SDK. Основание: карточка «тема… цвет шапки и фона Telegram из токенов» и
  поддержка старых клиентов (Bot API < 6.1); ТЗ §8 «корректная работа в Telegram для iOS, Android и
  компьютера». Поведение SDK стоит сверить с текущей версией `telegram.org/js/telegram-web-app.js`.

## 3. Безопасность клиента

- initData уходит только в тело `POST /auth/telegram` (`client.ts:84`). Токен лежит в приватном поле `Api`
  (`client.ts:67`); localStorage, sessionStorage, cookie, `console.*`, `location`/`history` в продуктовом
  коде не используются (проверено поиском). Запросы идут с `credentials: "omit"` и `cache: "no-store"`
  (`client.ts:161-162`), в `index.html:288` стоит `referrer: no-referrer`. Тесты проверяют хранилища,
  cookie, адрес и DOM (`App.test.tsx:84-94`), любой вывод в консоль роняет тест (`test/setup.ts`).
  Правило ESLint `no-console` действует.
- XSS: `dangerouslySetInnerHTML`/`innerHTML` нет. Данные сервера (имя пригласившего, имя партнёра, ссылка,
  контакты) выводятся текстом React. `href` строится только для `tel:` с фильтром `[^\d+]`
  (`Help.tsx:233-235`). Ссылка из ответа в `href` не попадает: в `t.me/share/url` она экранирована
  `encodeURIComponent` и открывается через `openTelegramLink` (`webapp.ts:148-153`).
- Токен приглашения проверяется по формату до запроса (`routes.ts:242`, `Incoming.tsx:241-244`)
  и кодируется в пути (`client.ts:117, 121`).
- Согласия и 18+ без отметки отправить нельзя: проверка `valid` в `submit` (`Onboarding.tsx:71`)
  плюс блокировка MainButton (`MainButton.tsx:191`). Константы `true` в теле допустимы, потому что
  до отправки проверены все четыре флажка. Сервер требует `const: true` — контракт.
- Ошибки сервера не журналируются. Тело ответа с ошибкой используется только как запасной текст
  незнакомого кода.
