## 5. Дефекты

- **D-1 [MINOR]** `backend/app/ai/llm/errors.py:63-70` (`LLMRefusal.fallback_ok = True`) — отказ модели
  (`stop_reason: refusal`) уходит на резервную модель. Это противоречит решению `DECISIONS.md` АР-20
  (принято A0 по A6 MINOR-3): резервная модель — только для недоступности (429/5xx/сеть/перегрузка),
  отказ — кризисный путь или понятное сообщение. Проверено: цепочка Opus (refusal) → Haiku вернула
  ответ Haiku. Ожидается: `LLMRefusal.fallback_ok = False`. Тест: `test_refusal_does_not_go_to_fallback`.
  Тяжесть MINOR, пока слой не используется в продукте. В продукте (0.5+) это MAJOR: отказ на
  кризисном тексте обходится более слабой моделью (§2 п.7, §9.3).
- **D-2 [MINOR]** `backend/app/ai/llm/claude.py:49-54` (клиент SDK без настройки журнала) — журнал SDK
  `anthropic._base_client` на уровне DEBUG пишет `Request options … json_data` с полным телом запроса:
  реплики, память, тексты сообщений пары. Для этого достаточно `DEBUG` у корневого журнала, переменная
  `ANTHROPIC_LOG` не нужна (проверено). Нарушает CLAUDE.md «в журналах нет текстов сообщений». Ключа в
  журнале нет. Ожидается: слой поднимает уровень журнала `anthropic` до `INFO` или ставит фильтр.
  Тест: `test_message_text_not_in_debug_logs`. Тяжесть MINOR: по умолчанию уровень `INFO`
  (`app/bot/setup.py:79`).
- **D-3 [MINOR]** `evals/compare.py:123-152` — если модель не ответила ни на одну ситуацию (529 на все
  запросы), `compare.py` возвращает 0 и пишет отчёт модели и сводку «0 % … $0.0000», хотя `run.py` в том
  же случае возвращает 3 и отчёт не пишет. Проверено на локальном сервере: код 0, файлы
  `x_claude-opus-5-5.{md,json}`, `x.{md,json}`, в строке сводки «Ошибки модели: 30». Ожидается: код ≠ 0 и
  пометка «модель не ответила» вместо качества 0 % (ТЗ §10, понятная ошибка при отказе). Тест:
  `test_cli_with_rejected_key_or_outage_fails_without_report[compare-перегрузка]`. Совпадает с A6 MINOR-6(а).
- **D-4 [MINOR]** `backend/app/ai/llm/pricing.py:29-30` — для модели без записи в `PRICES` (например,
  `claude-opus-5-5-20261101` или резервная, добавленная позже) `cost_usd` молча возвращает 0.0, и в
  сводке получается «$0.0000 на ситуацию». Ожидается: «цены нет» (`None` или ошибка конфигурации), а не
  0 (ТЗ §10 «контроль расходов»). Тест: `test_unknown_price_is_not_free`. Совпадает с A6 MINOR-4.
- **Подтверждаю 0.3 R2-MAJOR-1 [MAJOR]** `evals/run.py:740`, `evals/adapters/claude.py:240-255` — на
  шагах `converse` ключевого сценария в первом сообщении агента владельца есть
  `approved_partner_message` с текстом, который Анна одобрит только на шаге 3. Проверено на уровне HTTP:
  текст оригинала есть в теле каждого шага. Тест: `test_echo_owner_steps_do_not_see_approved_original`.
  Дефект учитывается в отчёте 0.3. Для 0.4 он блокирует открытый критерий «прогон по моделям»: на этом
  дефекте сравнение оценит ключевой сценарий недостоверно.

Наблюдения без дефекта:
- В продукте у клиента SDK по умолчанию `max_retries=2` (`claude.py:54`). Время ответа §10 при
  перегрузке включает повторы SDK до перехода на резервную. Для 0.4 это допустимо, настройку стоит
  решить в 0.5.
- В `summarize_metrics` p50/p95 считаются только по ситуациям без ошибок. Тайм-ауты в перцентили не
  попадают, число ошибок показано отдельно.
- Проверки A6 MINOR-1 (408/402/лимиты расходов) и MINOR-2 (`APIResponseValidationError`) A8 не
  дублировал: они в работе у исполнителя по ревью.
