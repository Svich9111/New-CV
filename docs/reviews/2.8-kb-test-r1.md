## 3. Дефекты

- **[MINOR-1]** `frontend/src/admin/texts.ts:9-26` — реальные коды сервера без своего текста. 500 сервера всегда
  приходит с JSON `{"code":"internal"}` (`backend/app/errors.py`, `_unhandled`), поэтому «Сбой на сервере» показывается
  только для ответа без JSON, а настоящий сбой — «Сервер ответил ошибкой (код «internal»)»; 409 `conflict_retry`
  (`_db_conflict`, АР-24) — тоже запасной текст. Тест A4 `KbScreen.test.tsx` «500 internal» закрепляет запасной текст.
  Критерий «все коды ответа — понятный текст» на настоящем сервере не выполнен. Тесты:
  `serverParity.a8.test.ts` `[MINOR-1] 500 internal…`, `[MINOR-1] 409 conflict_retry…` (`test.fails`). Совпадает с A6
  MINOR-1.
- **[MINOR-2]** `backend/app/api/admin_kb.py:53,236` (`MAX_FIELD_BYTES = 64 * 1024`, `max_part_size`) ↔
  `api/openapi.yaml` (`rights_basis` без `maxLength`, ответа 400 нет) ↔ `UploadForm.tsx:17-31` (длина основания прав не
  проверяется). Основание прав больше 64 КиБ (≈ 32 тыс. кириллических символов) уходит на сервер, Starlette отвечает
  400, обработчик — `{"code":"http_error"}` (проверено, §1), администратор видит «код «http_error»». Нужно решить у A1:
  `maxLength` в контракте (и проверка в клиенте) или 422 вместо 400. Тесты: `serverParity.a8.test.ts` (факт на сервере
  и в контракте, зелёный) и `[MINOR-2] 400 http_error…`; `KbScreen.a8.test.tsx` `[MINOR-2] основание прав длиннее
  предела…` (`test.fails`). Новое, у A6 нет.
- **[MINOR-3]** `frontend/src/admin/UploadForm.tsx:25-27` — длина считается в UTF-16 (`String.length`) и до
  `trim()`, а отправляется обрезанное значение; сервер (pydantic `max_length`, `length()` в PostgreSQL) считает символы.
  300 символов вне BMP и «300 символов + пробелы по краям» клиент отвергает, сервер принял бы. Тесты:
  `KbScreen.a8.test.tsx` `[MINOR-3] …` ×2 (`test.fails`). Совпадает с A6 MINOR-4.
- **[MINOR-4]** `frontend/src/admin/api.ts:188,197-198`, `Login.tsx:16-24` — токен с символом вне ISO-8859-1:
  `Headers` бросает `TypeError`, клиент считает его `network`, экран базы знаний показывает «Нет связи с сервером»,
  а не поле входа с «Токен не принят». Тест: `KbScreen.a8.test.tsx` `[MINOR-4] …` (`test.fails`). Совпадает с A6 MINOR-3.
  (Заодно: мой первый вариант теста 401 с повторным входом «другой-токен» упал ровно на этом.)
- **[MINOR-5]** `frontend/src/admin/KbScreen.tsx:45,87,102` — ответ `GET`, ушедшего до `POST`/`DELETE` и пришедшего
  после, целиком заменяет список: принятый материал пропадает, удалённый возвращается. Тесты: `KbScreen.a8.test.tsx`
  `[MINOR-5] …` ×2 (`test.fails`, падают на проверке после прихода старого ответа). Совпадает с A6 MINOR-2.

Замечания (не дефекты продукта, к тестам A4):

1. `boundary.test.ts` пропускает пять обычных нарушений (мутация в §1: `localStorage` после `"a//"`, склейка
   `"/api/v1/" + "memory"`, шаблонный `import()`, `window.name`, `fetch` вне `api.ts`) — подтверждает A6 MAJOR-1. Мой
   `boundary.a8.test.ts` ловит их и проверяет сборку по манифесту с динамическими импортами; при исправлении MAJOR-1
   A4 может взять его за основу или оставить оба.
2. `adminBuild.test.ts` собирает под vitest, где `NODE_ENV=test`: JSX собирается в отладочном виде, в чанке панели
   есть абсолютные пути файлов (`/home/…/src/admin/UploadForm`) — проверяется не та сборка, что выкладывается.
   `boundary.a8.test.ts` на время сборки ставит `NODE_ENV=production` (как `npm run build`).
3. `make lint` красный из-за неотслеживаемого `backend/tests/test_isolation_release_injection.py` другого
