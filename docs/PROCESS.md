# Цикл задачи и контроль соответствия ТЗ

Каждая фича проходит пять шагов. Шаг не пропускается, даже если задача маленькая.

```
 A0 карточка ─▶ Исполнитель (A1–A5, A7) ─▶ ┌ A6 Ревьювер ─┐ ─▶ замечания? ──да──▶ Исполнитель исправляет ─┐
                                            └ A8 Тестировщик┘        │                                     │
                                                    ▲                нет                                   │
                                                    └──────── повторная проверка ◀──────────────────────────┘
                                                                     ▼
                                                     A0: сверка с ТЗ, статус в ROADMAP.md, слияние
                                                                     ▼
                                                     Оператор: приёмка гейта этапа
```

## 1. Карточка (A0)

`docs/tasks/<номер>.md` по шаблону `docs/tasks/_TEMPLATE.md`: ссылка на ФТ и разделы ТЗ,
границы (что входит и что нет), проверяемые критерии готовности, список тестов.

## 2. Реализация (исполнитель)

Сначала тесты по критериям карточки, затем код. Перед сдачей: `make lint` и `make test` зелёные.

## 3. Ревью (A6) и тестирование (A8) — независимо и параллельно

Обоих запускают в новой сессии без контекста разработки. Они получают карточку, ТЗ и дифф —
не выводы исполнителя.

- **A6 Ревьювер**: корректность, безопасность и изоляция данных, соблюдение CLAUDE.md, качество
  кода, **сверка с ТЗ** (каждое требование карточки ↔ пункт ТЗ ↔ место в коде).
- **A8 Тестировщик**: прогоняет все проверки, пишет недостающие и негативные тесты по критериям,
  проверяет каждый критерий готовности фактом (вывод команды), а не чтением кода.

Отчёты: `docs/reviews/<номер>-review.md` и `docs/reviews/<номер>-test.md`. Формат замечания:
`[BLOCKER|MAJOR|MINOR] файл:строка — что не так — что ожидается (ссылка на ТЗ/карточку)`.

## 4. Исправления (исполнитель)

Все BLOCKER и MAJOR исправляются; MINOR — исправляются или переносятся карточкой в бэклог с
пометкой в отчёте. После исправлений — повторная проверка A6/A8 только по замечаниям.

## 5. Сверка с ТЗ и закрытие (A0)

A0 заполняет в карточке раздел «Сверка с ТЗ»: каждое требование — ✅ выполнено / ⚠️ допущение
(ссылка на `DECISIONS.md`) / ❌ отклонение (запрещено без решения оператора). Обновляет
`docs/ROADMAP.md` и `docs/TRACEABILITY.md`.

## Гейт этапа

На каждом гейте (Г0–Г6) A0 готовит сводку: какие ФТ этапа закрыты, какие тесты их подтверждают,
какие допущения остаются открытыми. Оператор принимает гейт и записывает решение в `DECISIONS.md`.
