# Экономия токенов агентов: RTK и Serena

Решение — `DECISIONS.md`, АР-15. Установка **глобальная — на все проекты пользователя**:
`infra/agent-tools/install.sh` (компьютер) и `infra/agent-tools/cloud-setup.sh` (облачные окружения).

| Средство | Что делает | Как подключено |
| --- | --- | --- |
| [RTK](https://github.com/rtk-ai/rtk) v1.2.1 | Сжимает вывод команд (git, pytest, ls, find…) до того, как его прочитает агент | Хук `PreToolUse` в `~/.claude/settings.json` переписывает `git status` → `rtk git status` и т. п. |
| [Serena](https://github.com/oraios/serena) 2.1.0 | MCP-сервер: поиск функций, классов и ссылок по символам вместо чтения целых файлов | Сервер уровня пользователя в `~/.claude.json`; проект определяется по текущему каталогу |

Оба работают локально, код открыт. Внешние обращения отключены: телеметрия RTK — `enabled = false`;
у Serena — `SERENA_USAGE_REPORTING=false` (иначе при запуске уходит ОС/версия на oraios-software.de)
и выключена веб-панель (проверка новостей и обновлений). Код и данные проекта никуда не отправляются.

## Установка

| Где | Как |
| --- | --- |
| Свой компьютер (Linux, macOS) | `bash infra/agent-tools/install.sh`, затем перезапустить Claude Code |
| Облачное окружение | Содержимое `infra/agent-tools/cloud-setup.sh` — в конец Setup script окружения. Уже добавлено в окружение New-CV |

Скрипт ставит RTK, пишет его настройки, добавляет хук в `~/.claude/settings.json` (остальные
настройки не трогает), регистрирует Serena на уровне пользователя (одобрять не нужно) и добавляет
`.serena/` в глобальный gitignore — Serena создаёт этот каталог в каждом проекте. Повторный запуск
дублей не создаёт. Проверка: `/mcp` в сессии или `claude mcp list` в любом проекте.

Serena сама определяет язык проекта, но берёт **один**. Для проекта на нескольких языках список
задаётся в его `.serena/project.yml` (`language_servers: [python, typescript]`), как в New-CV.

## Исключения RTK

Конфиг RTK бывает только пользовательский (`~/.config/rtk/config.toml`), его пишет `install.sh`.
Замер выявил две команды, где фильтр меняет результат — они исключены:

| Команда | Что ломалось |
| --- | --- |
| `npm run lint` | Переписывается в `rtk lint`: запускает только eslint, теряет `&& tsc -b --noEmit`, падает на разборе JSON; код выхода 2 вместо 0 |
| `tsc`, `npx tsc` | `rtk tsc` берёт глобальный TypeScript 6.0.2 вместо 5.7.2 проекта — ложная ошибка TS2882; код выхода 2 вместо 0 |

Если вывод сжат неудачно — `rtk bypass <команда>` или `rtk recall <id>` (id печатается в конце
сжатого вывода).

## Замер (2026-11-23)

Размер — в байтах вывода, который читает агент; токены ≈ байты / 4 (так же считает `rtk gain`).
Для текста на русском в UTF-8 абсолютные токены завышены, проценты от этого не зависят.

### RTK: команды проекта как есть и через хук

| Команда | Как есть | Через RTK | Экономия |
| --- | ---: | ---: | ---: |
| `pytest -q` (578 зелёных, 1 красный) | 20 531 | 2 816 | 86% |
| `pytest -v` | 81 228 | 2 933 | 96% |
| `git log -n 20` | 10 000 | 5 205 | 48% |
| `ls -la backend/app` | 689 | 201 | 71% |
| `find backend -name '*.py'` | 1 218 | 767 | 37% |
| `git status` (чистое дерево) | 73 | 55 | 25% |
| `git diff` (коммит 0.7b, в основном .md) | 25 276 | 24 977 | 1% |
| `grep -rn user_id`, `git show --stat`, `ruff`, `mypy`, `vitest`, `cat docs/TZ.md` | 53 090 | 53 090 | 0% |
| **Итого 15 команд** | **192 541** | **90 480** | **53%** |

- Ошибка в сжатом выводе `pytest` сохранена: имя упавшего теста, причина (`InvalidPasswordError`),
  строка итогов и команда `rtk recall` для полного вывода. Коды выхода совпадают во всех случаях.
- `pytest -v` как есть (81 КБ) больше лимита вывода Claude Code (~30 тыс. символов) и обрезается —
  без RTK агент не увидел бы итог и упавший тест.
- Основная выгода — в тестах и логах; короткие выводы и чтение файлов RTK не трогает.

### Serena: тот же вопрос через инструменты Serena и через grep + Read

«Наивно» — прочитать файл целиком; «аккуратно» — `grep -n`, затем Read только нужных строк
(лишний ход агента).

| Вопрос | Наивно | Аккуратно | Serena | vs наивно | vs аккуратно |
| --- | ---: | ---: | ---: | ---: | ---: |
| Функция `complete_onboarding` и кто её вызывает | 9 902 | 2 725 | 2 310 | 77% | 15% |
| Обзор `models/tables.py` (454 стр.) | 23 806 | 1 383 | 489 | 98% | 65% |
| Тело класса `PartnerMessage` | 23 806 | 3 619 | 3 475 | 85% | 4% |
| Один тест из `test_rls_a8.py` (1274 стр.) | 69 964 | 1 630 | 1 629 | 98% | 0% |
| Где используется `User` | 140 | 140 | 386 | −176% | −176% |
| TS-компонент `App` (8 стр.) | 233 | 233 | 331 | −42% | −42% |
| **Итого** | **127 851** | **9 730** | **8 620** | **93%** | **11%** |

- Ответы Serena проверены вручную — совпадают с grep и чтением файлов.
- Цена: описания 21 инструмента Serena — 28,9 КБ (~7 тыс. токенов) при загрузке в сессию.
  Claude Code подгружает схемы MCP по требованию, но окупается это только при работе с кодом,
  а не с документами.
- Выгода растёт с размером файлов. Сейчас код продукта — ~1200 строк, крупное — тесты и модели;
  на мелких файлах и простых поисках Serena дороже grep.
