## Границы

Этап 1 (сейчас): формат набора, первые 30 ситуаций (черновик A3), критерии оценки, скрипт прогона с заглушкой
модели. Этап 2: до 100 ситуаций. Утверждение — только психологом (Д5); до утверждения набор помечен
`status: draft` и гейты качества по нему не принимаются.
Не входит: слой над языковой моделью и сравнение моделей (0.4), промпты v0 (0.5).

## Критерии готовности (этап 1)

- [x] Формат `evals/situations/*.yaml` описан схемой (`evals/schema.json`) и проверяется тестом.
- [x] 30 ситуаций: уровни 1–5 по §6.4 (не меньше 4 на уровень), из них ≥ 6 контрольных примеров уровня 5
      по всем строкам таблицы §9.3 (насилие, угрозы в исходящем, самоповреждение, угроза жизни, младше 18);
      ключевой сценарий «Анна и Игорь» — отдельной ситуацией.
- [x] Каждая ситуация: реплика(и) владельца, ожидаемый уровень, ожидаемая стратегия по §6.4, для ситуаций с
      сообщением партнёру — исходное резкое сообщение, недопустимые искажения смысла (факты, просьба, без
      обещаний и извинений от имени автора, §6.2 п.5), для уровня 5 — ожидаемое поведение кризисного протокола.
- [x] Набор проверок на «переводчик, а не адвокат», приватность (агент не пересказывает чужое, §9.2 п.2) и
      инструкции в тексте входящего сообщения (§9.2 п.3) — не меньше 3 ситуаций.
- [x] Критерии оценки (`evals/RUBRIC.md`): что считается «смысл сохранён», «меня услышали» (шкала 1–5),
      «кризис распознан»; кто и как оценивает (автоматически / психолог).
- [x] Скрипт `evals/run.py`: прогоняет набор через интерфейс модели (сейчас — детерминированная заглушка),
      выдаёт отчёт markdown + json: по уровням, доля распознанных кризисов, заготовка под оценку психолога;
      сравнивает с прошлым отчётом. Тесты скрипта в CI.
- [x] Все тексты выдуманные, без реальных людей; на русском; тон §2.
- [x] Набор помечен «черновик — ждёт утверждения психологом» (Д5).
