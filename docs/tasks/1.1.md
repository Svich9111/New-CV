## Границы

Входит: проверка подписи и срока initData, создание/поиск пользователя по telegram_id, сессия (JWT),
зависимость «текущий пользователь», `POST /auth/telegram`, `GET /me`, ошибки в формате контракта.
Не входит: онбординг и согласия (1.2), пары (1.3), повторная регистрация после удаления (4.5),
открытие Mini App из бота (1.4).

## Критерии готовности

- [x] Поддельная подпись отклоняется — есть тест (RoadMap 1.1).
- [x] Подменённое или добавленное поле, дублирующиеся ключи, отсутствие hash — отклоняются.
- [x] Просроченный initData (старше `FEELINGS_INIT_DATA_MAX_AGE_S`, 24 ч) и auth_date из будущего — отклоняются.
- [x] Пустой токен бота в конфигурации не позволяет войти.
- [x] Успешный вход создаёт пользователя один раз; повторный вход — тот же пользователь.
- [x] При отказе пользователь в БД не создаётся.
- [x] Эндпоинты кроме входа и health требуют сессию; чужая/просроченная/подделанная сессия — 401.
- [x] Сохраняется только telegram_id; имя из Telegram не сохраняется (имя спрашивается в 1.2).
- [x] Ответы — по контракту `api/openapi.yaml` (Session, Me, Error); тело запроса не отражается в ошибках.
