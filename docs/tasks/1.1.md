## Границы

Входит: проверка подписи и срока initData, создание/поиск пользователя по telegram_id, сессия (JWT),
зависимость «текущий пользователь», `POST /auth/telegram`, `GET /me`, ошибки в формате контракта.
Не входит: онбординг и согласия (1.2), пары (1.3), повторная регистрация после удаления (4.5),
открытие Mini App из бота (1.4).

## Критерии готовности

- [ ] Поддельная подпись отклоняется — есть тест (RoadMap 1.1).
- [ ] Подменённое или добавленное поле, дублирующиеся ключи, отсутствие hash — отклоняются.
- [ ] Просроченный initData (старше `FEELINGS_INIT_DATA_MAX_AGE_S`, 24 ч) и auth_date из будущего — отклоняются.
- [ ] Пустой токен бота в конфигурации не позволяет войти.
- [ ] Успешный вход создаёт пользователя один раз; повторный вход — тот же пользователь.
- [ ] При отказе пользователь в БД не создаётся.
- [ ] Эндпоинты кроме входа и health требуют сессию; чужая/просроченная/подделанная сессия — 401.
- [ ] Сохраняется только telegram_id; имя из Telegram не сохраняется (имя спрашивается в 1.2).
- [ ] Ответы — по контракту `api/openapi.yaml` (Session, Me, Error); тело запроса не отражается в ошибках.
