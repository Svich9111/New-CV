## Границы

Входит (`frontend/`):

- Маршрут `memory` (`src/app/routes.ts`), экран `src/screens/Memory.tsx`; «Назад» — BackButton Telegram и кнопка в
  странице.
- Вход: главный экран «Вы пара» (`Paired.tsx`) и экран приглашения (`Invite.tsx`) — пункт «Что агент помнит» (экрана
  «Профиль и пара» ещё нет; когда появится — вход переносится туда, как в прототипе). Сервер отдаёт память без
  онбординга (АР-17, АР-25); клиент показывает вход там, где пользователь уже вошёл.
- `GET /memory` одним запросом (без `type`), группировка на клиенте по шести типам ТЗ §6.3 в порядке таблицы:
  «Факты», «Важные даты» (с `event_date`), «Предпочтения», «Чувствительные темы», «Наблюдения агента» (подпись «вывод
  агента, а не твои слова» — `source: agent_inference`), «Из сообщений партнёра» (подпись «из сообщений, которые
  партнёр тебе отправил» — `source: partner_message`). Пустые категории — не показываются или с подписью «пока
  пусто» (по прототипу); весь экран пуст — объяснение, откуда берутся записи.
- Пояснение на экране: «Партнёр и его агент этого не видят» (§8, §2 п.4).
- Удаление: «Удалить» у каждой записи → подтверждение на месте («Удалить навсегда? Агент больше не вспомнит это.» —
  «Удалить» / «Отмена»), `DELETE /memory/{id}`: 204 — запись убрана; 404 — запись уже удалена (другое устройство) —
  убрана, нейтральная подпись; 409 `conflict_retry` — один автоповтор, затем «Не получилось удалить, попробуй ещё
  раз»; сеть/5xx — запись остаётся, подпись и «Повторить»; 401 — один повторный вход (как в 1.5/2.2). Двойное
  нажатие — один запрос.
- `UnavailableText` (текст не расшифровался) — «Текст записи недоступен», запись можно удалить (контракт).
- Ответ не по схеме (строгая проверка `MemoryItem`: тип, источник, уверенность 0–1, дата) — «Память пришла с
  ошибкой», ничего чужого на экране.
- Уверенность (`confidence`) — не показывается числом; см. вопрос 3.
- Строгие проверки вида ответа в `src/api/` (как `ChatMessage` в 2.2), методы `memoryList`, `memoryDelete` в
  `src/api/client.ts`, тексты ошибок — `src/api/messages.ts` (операции `memoryList`, `memoryDelete`).
- Заглушка `src/test/fakeApi.ts`: `GET /memory` (шесть типов, `UnavailableText`, `?type`), `DELETE /memory/{id}`
  (204, повтор — 404, чужой id — 404, 409 по `inject`), учёт удалённых — повторный `GET` их не возвращает.

Не входит: сервер и контракт (не меняются); правка записи (ТЗ не требует); «удалить всё» (не в ТЗ — вторая очередь,
см. вопрос 4); экран «Профиль и пара»; напоминания о датах (ФТ-22, вторая очередь).

## Критерии готовности

- [x] Записи показаны по шести категориям ТЗ §6.3; наблюдения агента и записи из сообщений партнёра визуально и

- [x] 404 при удалении — запись убрана без ошибки; 409 — один автоповтор; сеть/5xx — запись на месте, «Повторить»;

- [x] Тексты записей — только текст React (без `dangerouslySetInnerHTML`; XSS в записи — текст); не попадают в консоль,

## Заметки A4

Сделано на заглушке (сервер и контракт не менялись). Клиентская часть критериев — `[x]`; серверная сторона критерия
«удаление подтверждается проверкой в БД» — прогон A8 (`backend/tests/test_memory_api.py`), Г1/Г2 — оператор.

- **Файлы.** `src/api/memory.ts` (новый: `MEMORY_TYPES`, `isMemoryItem`, `isMemoryList`, `isDay`); `src/api/client.ts`
  (`memoryList()` → `MemoryItem[]`, `memoryDelete(id)` → `"deleted" | "gone"`); `src/api/messages.ts` (операции
  `memoryList`, `memoryDelete`); `src/api/types.ts` (`MemoryType`, `MemoryItem`, `MemoryList` из `schema.d.ts`);
  `src/app/routes.ts`, `src/app/App.tsx` (маршрут `memory`); `src/screens/Memory.tsx` (новый); `src/screens/Paired.tsx`
  (карточка-ссылка «Что агент помнит»), `src/screens/Invite.tsx` (кнопка «Что агент помнит»); `src/app.css` (блок
  «Что агент помнит», только токены); `src/test/fakeApi.ts` (`GET /memory`, `DELETE /memory/{id}`, `seedMemory`,
  `addMemory`, `deletedMemory`, `partnerMemory`).
- **Строгая проверка `MemoryItem`.** id — uuid (уходит в путь `DELETE`); тип и источник — из перечней контракта;
  текст — `ExportText` (общий `isExportText` из 2.2); `event_date` — нет поля, `null` или существующий день
  `YYYY-MM-DD` (не дата-время, не 30 февраля); `confidence` — конечное число 0–1; `created_at` — разбираемая дата.
  Одна неверная запись или повтор id — весь ответ `bad_response`, экран «Память пришла с ошибкой…» и ни одной записи.
- **Удаление.** `DELETE /memory/{id}` без тела и без строки запроса; уходит только после «Удалить навсегда» в
  подтверждении на месте. 204 — `deleted`; 404 — `gone` (запись убрана, подпись «Эта запись уже была удалена.»,
  без `role=alert`); 409 `conflict_retry` — общий автоповтор клиента (ровно один), затем «Не получилось удалить,
  попробуй ещё раз.» и «Повторить»; 401 — общий повторный вход; сеть/срок/5xx/непонятный ответ — запись на месте,
  подпись и «Повторить» (повтор без второго подтверждения — подтверждение уже дано). Иной 2xx вместо 204 —
  `bad_response`, а не «удалено». Двойное нажатие и нажатие во время запроса — один запрос (`inFlight` по id; кнопка
  записи на время запроса — «Удаляем…», `aria-disabled`, не `disabled`, чтобы фокус не терялся).
- **Текст подтверждения** — «Удалить навсегда? Запись не восстановится, и агент не запомнит это снова.» вместо
  «…Агент больше не вспомнит это.» из «Границ»: по АР-37 (на подтверждении) удалённое остаётся в последних репликах
  личного чата и может снова попасть в сводку при сжатии, так что «больше не вспомнит» обещает больше, чем делает
  сервер. Новый текст говорит только о том, что гарантирует §6.3 (не восстанавливается, не извлекается повторно); про
  сводки — ничего (тест `CONFIRM_TEXT`). После решения по АР-37 — правка одной константы (вопрос 5).
- **Категории** — названия прототипа («Факты», «Важные даты»…), порядок таблицы §6.3; пустая категория — «Пока пусто»
  (как прототип); весь экран пуст — объяснение, откуда берутся записи. Отделение не своих слов: подпись под заголовком
  категорий «Наблюдения агента» («Вывод агента, а не твои слова.») и «Из сообщений партнёра» («Из сообщений, которые
  партнёр тебе отправил.»); у каждой записи с источником `agent_inference`/`partner_message` — значок-подпись
  («вывод агента, а не твои слова» / «от партнёра») и полоса слева, независимо от типа (вывод агента с типом `fact`
  тоже помечен); строка «Источник: твои слова / вывод агента / сообщение партнёра · дата создания». У записи с
  `event_date` — «Дата: 14 июня 2027 г.» (день как есть, без сдвига часового пояса).
- **Уверенность** числом не показывается; по предложению A0 (вопрос 3) у выводов агента с `confidence` < 0,5 — «агент

## Предложения к контракту (для A1)

Нет. Все записи одним ответом пока достаточно; постраничный вывод понадобится, если записей станет сотни — тогда
предложение отдельной карточкой.

## Вопросы оператору

1. Названия категорий на экране — по таблице ТЗ §6.3 («Факт», «Важная дата»…) или по прототипу? (Г1)
2. Где вход на экран до появления «Профиля и пары»: главный экран — достаточно?
3. Показывать ли уверенность записи (§6.3 «каждая запись хранит … уровень уверенности») — словами («агент не уверен»)
   при `confidence` < 0,5 или не показывать вовсе? Предложение A0: показывать подпись только для наблюдений агента.
4. «Удалить всё» — нужно ли в первой очереди? ТЗ требует удаление любой записи; предложение — вторая очередь.
5. АР-37 — подтвердить (влияет на текст подтверждения удаления).
