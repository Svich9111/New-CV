- Кредиты OpenRouter исчерпаны: модель — заглушка в тестах; живой замер «первый символ ≤ 5 с» — после пополнения.
- Промпты v0 — только прототип (АР-26): эндпоинт работает на наборе по умолчанию, но в продукт (Г3) — после прогона.
- Память (2.4) и база знаний (2.6) ещё не наполняются: сборка контекста читает то, что есть; поиск «по смыслу» — через
  интерфейс эмбеддингов с заглушкой (настоящая модель эмбеддингов — решение A3/оператора, без кредитов не проверить).
- Прогон потокового режима (`stream_text` без строгой схемы) на `dialog.v0`/`dialog.v1` и выбор `dialog.v1` по умолчанию — условие Г3 (ревью 2.1 MINOR-9).
- Подписка и оплата (этап 4) не сделаны: 402 не отдаётся, пока нет логики подписки (описать в отчёте и BACKLOG).

## Границы

Этап 1 (A3): `backend/app/ai/context.py` — сборка контекста строго по §6.1 из данных владельца через слой доступа
(`repositories/`, под `user_scope`): профиль и сводка памяти (`agents.profile_summary_enc`), записи памяти по смыслу
реплики (интерфейс `Embedder`, заглушка; без эмбеддинга — по свежести, с ограничением числа), фрагменты базы знаний
(интерфейс, пусто до 2.6), последние реплики и сводка предыдущих (`conversations.summary_enc`), одобренные сообщения пары
по теме (только доставленные; адаптированная версия — как её видел владелец). Нет данных партнёра, его памяти и чата.
Бюджет контекста (токены/символы) и усечение. Сжатие истории: при превышении — сводка старых реплик моделью
(новый промпт `summary.v0.md`, прогон — после кредитов, АР-26) в `summary_enc`. Потоковый диалог поверх `dialog.py`
(`LLMProvider.stream_text`), вторая линия безопасности до первого символа или параллельно — так, чтобы кризисный ответ
шёл всегда (§9.3), а отказ модели давал понятное сообщение без потери реплики (§10, АР-20).
Этап 2 (A2): `POST /chat/messages` — SSE (`delta`, `done`, `crisis`, `error` по контракту), сохранение реплики владельца
до вызова модели (не теряется при отказе), сохранение ответа агента; `GET /chat/messages` — история с курсором;
лимит запросов в сутки (Redis или БД — опиши; при кризисе 429 не отдаётся); журналы без текстов.
Правила для этапа 2 (ревью р.3): классификатору передаётся `built` целиком (`screen(models, built)`), не срез/копия `built.dialog` — тест на вход классификатора при усечении; поток в обработчике SSE — в `contextlib.aclosing(...)`, тест на отключение клиента (вызовы модели отменены).
Не входит: голос (2.3), извлечение памяти (2.4), база знаний (2.6), черновик в чате (3.1 — `suggest_draft` только флаг).

## Критерии готовности

- [ ] Контекст содержит только данные владельца и одобренные сообщения его пары — тест с метками партнёра, бывшего партнёра и постороннего (критерий RoadMap); изоляция обеспечена `user_scope`/RLS, а не промптом.
- [ ] Состав и порядок блоков контекста — по §6.1; бюджет соблюдается; усечение не выбрасывает системный промпт и последнюю реплику.
- [ ] Сжатие истории: сводка хранится зашифрованной, старые реплики в контекст не идут; удалённая запись памяти в контекст не попадает.
- [ ] SSE по контракту; первый `delta` не ждёт полного ответа (тест на заглушке с задержкой); кризис — событие `crisis` с контактами всегда, без 402/429.
- [ ] Отказ/недоступность модели — событие `error`, реплика владельца сохранена; резервная модель — только при недоступности (АР-20).
- [ ] Лимит запросов в сутки; журналы и `audit_log` без текстов.
