## Границы

Входит: `infra/deploy/` — Docker Compose стенда (Caddy/HTTPS наружу, PostgreSQL/Redis только во внутренней сети,
тома, health checks), образы backend и caddy, `init-owner.sql` (владелец схемы `feelings_owner`), `roles.sql` (роли
входа API/воркеров/админа), `gen_secrets.py` (секреты только на сервере), `backup.sh`/`restore-check.sh`,
`bootstrap.sh`, `docs/DEPLOY.md`, `docs/ADMIN.md`. Стенд — `FEELINGS_ENV=staging`, не production.
Не входит: выкладка на сервер (только по подтверждению оператора), production, задача 4.7 (регламент копий продукта).
Автоматическая выкладка main на стенд — отложена до появления сервера и решения оператора (АР-43).

## Критерии готовности

- [ ] Наружу только 80/443; PostgreSQL и Redis — внутренняя сеть, без портов.
- [ ] Секретов и заглушек в Git нет; обязательные переменные без значения — отказ запуска; пароль суперпользователя отдельно.
- [ ] Миграции — под `feelings_owner` (не суперпользователь), приложение — `feelings_api` только с SET ROLE `feelings_app`; автотесты на это.
- [ ] Health checks у всех долгоживущих сервисов; порядок запуска по готовности.
- [ ] Резервная копия, ротация 30 дней, проверка восстановления — включая права уровня базы (АР-10).
- [ ] `docs/DEPLOY.md`: установка, обновление, откат, DNS, порты, перечень секретов, восстановление.
- [ ] Локальный подъём стека в Docker проверен; lint, тесты (trust и scram), сборка — зелёные.
