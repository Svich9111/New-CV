## Границы

Входит: `backend/app/ai/llm/` — интерфейс поставщика (сообщения, системный промпт, структурированный ответ,
потоковый вывод — интерфейс, без реализации чата), реализация для Claude API (официальный SDK `anthropic`),
резервная модель и понятная ошибка при отказе (§10); адаптер к `evals/run.py`, в котором доставка сообщения
партнёру строится отдельным вызовом только по оригиналу (ревью 0.3 MAJOR-1, ТЗ §6.2 последний абзац);
сбор метрик: время до первого токена/ответа, токены, стоимость по прайсу; сводная таблица
«качество / скорость / цена» по 2–3 моделям.
Не входит: промпты v0 (0.5) — для сравнения используется рабочий системный промпт сравнения в `prompts/`
с пометкой «для 0.4», окончательный выбор модели (после утверждения набора психологом).

## Критерии готовности

- [x] Слой не зависит от конкретного поставщика; ключ — только из окружения (`ANTHROPIC_API_KEY`). — `backend/app/ai/llm/base.py` (`LLMProvider`), `claude.py`, `fallback.py`; `test_no_api_key_is_config_error`
- [x] Без ключа прогон завершается понятной ошибкой, ничего не выдумывая; тесты работают без сети (подменённый транспорт). — код 3, отчёт не пишется: `test_cli_without_key_fails_clearly`, `test_compare_without_key_fails_clearly`; транспорт `httpx2.MockTransport`
- [x] Агент получателя получает только оригинал сообщения; тест на это с моделью-«эхом». — `test_recipient_call_gets_only_original`
- [x] В запросах нет идентификаторов Telegram и имён из профиля сверх нужных (§9.1 п.4). — `test_request_shape_adaptive_structured_no_ids`, `test_owner_call_gets_only_owner_data` (только имена пары; у агента получателя имён нет)
- [ ] Команда одного прогона по моделям и отчёт сравнения в `evals/reports/` (качество по проверкам набора, p50/p95 время, токены и $ на ситуацию). — команда и формат готовы (`evals/compare.py`, `test_compare_table` на подменённом транспорте); **сам прогон ждёт ключ**, результаты не выдумываются

## Примечания исполнителя (A3)

- Время до первого токена: в сравнении измеряется время полного ответа на ситуацию (структурированный
  JSON не показывается по частям); потоковый вывод `stream_text` для чата готов в слое и проверен
  тестом, TTFT чата — в 0.5.
- Серверный `fallbacks` Claude API в сравнении не включён: каждая модель должна измеряться как есть.
  Резервная модель — `FallbackProvider` слоя (переход при недоступности, отказе, испорченном ответе).
- «Кризис распознан» (§12 п.6) — только по оценке эксперта (ревью 0.3 MAJOR-3): адаптер не
  выставляет `safety_event` сверх того, что вернула модель; `partner_notified` всегда `False`.
- §9.1 п.4 «поставщик не обучается на данных» — условие договора с поставщиком, кодом не проверяется.
