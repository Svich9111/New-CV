## Границы

Входит: `PUT /me/onboarding` по контракту (имя, обращение, имя партнёра, часовой пояс, три согласия, 18+);
создание личного агента пользователя (строка `agents`) при завершении онбординга; зависимость FastAPI
`OnboardedUser` для всех будущих эндпоинтов, требующих онбординга; `GET /me` отражает `onboarding_completed`.
Не входит: тексты соглашений (4.6 — юрист), экраны (1.5), пары (1.3).

## Критерии готовности

- [ ] Без всех трёх согласий (`consent_terms`, `consent_data`, `consent_sensitive`) онбординг не завершается — 422.
- [ ] `age_confirmed=false` → 403 `underage`, согласия не сохраняются, пишется `safety_events` с типом `underage`
      без личных данных; доступ к сервису не предоставляется (ТЗ §9.3).
- [ ] Успешный онбординг: поля и время согласий сохранены, создан ровно один агент; повтор — идемпотентен
      (обновляет поля, второго агента нет).
- [ ] Зависимость `OnboardedUser`: без завершённого онбординга — 403 `onboarding_required`. Критерий RoadMap
      «Без согласий доступ к чату закрыт» подтверждается тестом на защищённом маршруте (сам чат — 2.1).
- [ ] Валидация длины полей по контракту (1–64), часовой пояс — существующая зона IANA.
- [ ] Ответ — схема `Me` контракта; тело запроса не отражается в ошибках; SQL только в `repositories/`.
