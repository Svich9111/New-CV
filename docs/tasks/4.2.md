## Границы

Входит: модуль `backend/app/core/crypto.py` — шифрование на уровне приложения (AES-256-GCM, библиотека `cryptography`),
формат шифротекста с версией ключа (ротация: новые записи — текущим ключом, чтение — любым из набора), связанные данные (AAD:
таблица, колонка, id строки) против перестановки шифротекстов между строками; ключи — только из окружения
(`FEELINGS_ENCRYPTION_KEYS` — набор `id:base64`, `FEELINGS_ENCRYPTION_KEY_ID` — текущий); сервис не стартует без ключа;
применение в существующем коде: `message_drafts.text_enc`, `partner_messages.original_enc/adapted_enc`, `conversation_messages.text_enc`,
`memory_items.text_enc`, `conversations.summary_enc`, `agents.profile_summary_enc` — функции слоя доступа шифруют при записи и
расшифровывают при чтении (где запись/чтение уже есть; где ещё нет — помощники для 2.x/3.x); проверка «в БД и журналах нет открытого
текста» (критерий RoadMap).
Не входит: обезличивание перед отправкой в модель (часть 4.2 по RoadMap — после 2.1, когда появится сборка контекста; запиши в
BACKLOG), ротация ключа в продуктиве (регламент — 4.7).

## Критерии готовности

- [ ] Шифрование/расшифровка: AES-256-GCM, случайный nonce 96 бит на запись, версия ключа в заголовке, AAD; подмена байта, чужой AAD, чужой ключ → ошибка, не мусор.
- [ ] Ротация: данные под старым ключом читаются, новые — пишутся текущим; функция перешифровки (для 4.7).
- [ ] Без ключа / с ключом неверной длины сервис не стартует; ключ и открытые тексты не попадают в журналы и исключения.
- [ ] Функции БД (`app_send_draft`, `pipeline_*`) работают с шифротекстом как с непрозрачными байтами — проверено тестом.
- [ ] Критерий RoadMap: после записи через слой доступа в БД нет открытого текста (поиск подстроки по всем bytea/text колонкам), в журналах (caplog) — тоже.
- [ ] Тесты без сети; `make lint`, `make test` зелёные.
