## Границы

Входит: модуль `backend/app/core/crypto.py` — шифрование на уровне приложения (AES-256-GCM, библиотека `cryptography`),
формат шифротекста с версией ключа (ротация: новые записи — текущим ключом, чтение — любым из набора), связанные данные (AAD:
таблица, колонка, id строки) против перестановки шифротекстов между строками; ключи — только из окружения
(`FEELINGS_ENCRYPTION_KEYS` — набор `id:base64`, `FEELINGS_ENCRYPTION_KEY_ID` — текущий); сервис не стартует без ключа;
применение в существующем коде: `message_drafts.text_enc`, `partner_messages.original_enc/adapted_enc`, `conversation_messages.text_enc`,
`memory_items.text_enc`, `conversations.summary_enc`, `agents.profile_summary_enc` — функции слоя доступа шифруют при записи и
расшифровывают при чтении (где запись/чтение уже есть; где ещё нет — помощники для 2.x/3.x); проверка «в БД и журналах нет открытого
текста» (критерий RoadMap).
Не входит: обезличивание перед отправкой в модель (часть 4.2 по RoadMap — после 2.1, когда появится сборка контекста; запиши в
BACKLOG), ротация ключа в продуктиве (регламент — 4.7).

## Критерии готовности

- [x] Шифрование/расшифровка: AES-256-GCM, случайный nonce 96 бит на запись, версия ключа в заголовке, AAD; подмена байта, чужой AAD, чужой ключ → ошибка, не мусор.
- [x] Ротация: данные под старым ключом читаются, новые — пишутся текущим; функция перешифровки (для 4.7).
- [x] Без ключа / с ключом неверной длины сервис не стартует; ключ и открытые тексты не попадают в журналы и исключения.
- [x] Функции БД (`app_send_draft`, `pipeline_*`) работают с шифротекстом как с непрозрачными байтами — проверено тестом.
- [x] Критерий RoadMap: после записи через слой доступа в БД нет открытого текста (поиск подстроки по всем bytea/text колонкам), в журналах (caplog) — тоже.
- [x] Тесты без сети; `make lint`, `make test` зелёные (backend: ruff, ruff format --check, mypy, pytest — 1438 passed, 6 xfailed).

## Реализация (A2)

- `backend/app/core/crypto.py` — `Keyring` (шифрует текущим ключом, расшифровывает любым из набора), `Field`
  (таблица/колонка → AAD), `parse_keyring`/`load_keyring` (проверка при старте), `reencrypt`/`reseal`/`needs_rotation`/
  `key_id_of` (ротация, 4.7), `generate_key_entry` (новый ключ для `.env`). Ошибки — `DecryptionError(reason)` с кодом
  `format|unknown_key|auth|encoding` и `KeyConfigError` (подкласс `ConfigError`) — без значений ключей и текстов, без
  цепочки исходных исключений. Модуль ничего не пишет в журналы.
- Формат шифротекста v1: `0x01 | len(key_id) | key_id (ASCII, 1–32 символа A-Z a-z 0-9 _ -) | nonce 12 байт |
  шифротекст + тег 16 байт`. Связанные данные GCM = заголовок (версия, id ключа) + `«таблица|колонка|id строки»` —
  подмена версии/id ключа тоже отвергается.
- Ключи: `FEELINGS_ENCRYPTION_KEYS` = `id:base64url(32 байта)` через запятую, `FEELINGS_ENCRYPTION_KEY_ID` — текущий.
  В `config.py` прежнее `encryption_key` заменено двумя полями (изолированная правка). `app/main.py`: `lifespan` вызывает
  `load_keyring` до создания движка БД и кладёт набор в `app.state.keyring`; пустой набор, неверная длина (16/31/33/34
  байта), битый base64, повтор id, текущий id вне набора — сервис не стартует.
- **AAD оригинала сообщения пары.** `app_send_draft` копирует `message_drafts.text_enc` в `partner_messages.original_enc`
  байт в байт и сама создаёт id сообщения, а ключа не знает. Поэтому оригинал расшифровывается с контекстом черновика:
  `message_drafts|text_enc|<partner_messages.draft_id>` (`crypto.MESSAGE_ORIGINAL = DRAFT_TEXT`). Защита от перестановки
  сохраняется: у каждого сообщения свой черновик (`draft_id` — колонка самой строки сообщения), чужой оригинал,
  подставленный в сообщение, не расшифровывается (тест). Миграция не нужна. Альтернативы отвергнуты: AAD без id строки
  (позволяет переставлять тексты между строками) и перешифровка в функции БД (ключ в БД — против ТЗ §5). Ограничения —
  BACKLOG Б-38 (удаление отправленного черновика обнуляет `draft_id`) и Б-39 (`pipeline_original` не отдаёт `draft_id`).
  Версия для получателя `adapted_enc` шифруется конвейером с контекстом `partner_messages|adapted_enc|<id сообщения>`
  (и при копии оригинала — тоже перешифровка, не копирование байтов).
- Применение: в коде до 4.2 тексты нигде не писались и не читались (эндпоинты чата, памяти, черновиков и ленты — 2.x/3.x),
  поэтому добавлен слой доступа `backend/app/repositories/texts.py` — функции для всех семи колонок из границ карточки:
  диалог (`add_conversation_message`, `list_conversation_messages`), резюме диалога и профиля агента
  (`set/get_conversation_summary`, `set/get_agent_profile_summary`), память (`add_memory_item`, `list_memory_items`),
  черновик (`create_draft`, `update_draft_text`, `get_draft`), отправка (`send_draft`), лента (`read_feed`), оригинал
  (`read_original`), конвейер (`pipeline_read_original`, `pipeline_deliver` — сессия под `feelings_worker`). Всё — внутри
  `user_scope` (RLS, проверка владельца), id строки создаёт приложение до записи. Задачи 2.x/3.x пишут тексты только
  через эти функции; набор ключей берут из `app.state.keyring`.
- Обезличивание перед моделью — BACKLOG Б-37 (после 2.1).
- Тестовая фикстура `world` (test_rls_isolation) по-прежнему заводит открытые байты (заглушка АР-8); тесты 4.2 убирают их
  (`encrypted_world`), слой доступа такие записи отвергает (`DecryptionError`). В `conftest.py` — автофикстура с выдуманным
  тестовым набором ключей в окружении для тестов запуска сервиса.
