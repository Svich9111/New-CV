## Границы

Входит: 17 таблиц §7, миграция Alembic (обратимая), роли БД, политики RLS, вспомогательные функции
входа и приглашений, контракт `api/openapi.yaml` на все пользовательские ФТ первой очереди,
`user_scope` — транзакция от имени пользователя.
Не входит: бизнес-логика эндпоинтов (1.1–4.5), шифрование (4.2), принятие приглашения (функция
SECURITY DEFINER — 1.3), векторные индексы (2.4, 2.6).

## Критерии готовности

- [x] В схеме ровно 17 таблиц §7 с ключевыми полями из §7.
- [x] Миграция проходит upgrade → downgrade → upgrade.
- [x] RLS включён на всех таблицах с личными данными; личный чат, черновики и память видит только
      владелец; сообщения пары — только двое участников; посторонний не видит ничего.
- [x] Нельзя писать в чужую память и отправлять сообщение от имени партнёра или в чужую пару.
- [x] Одна активная пара на пользователя; не больше двух участников пары.
- [x] Вступить в пару без приглашения и активировать пару в одиночку нельзя.
- [x] `safety_events` и `audit_log` без текстов; роль приложения их не читает; админ не видит переписки.
- [x] Тексты переписки, памяти, черновиков — только bytea.
- [x] Контракт — валидный OpenAPI 3.1, покрывает пользовательские ФТ-01…ФТ-21; публичны только вход и health.
