## Границы

Входит (A2): эндпоинты контракта `GET /couple`, `POST /couple`, `POST /couple/invite`, `GET /invites/{token}`,
`POST /invites/{token}/accept`, `POST /couple/leave` — через функции БД `app_create_couple`, `app_issue_invite`,
`app_find_invite`, `app_accept_invite`, `app_leave_couple`, `app_couple_members`; генерация токена (32 случайных
байта, base64url, в БД — только SHA-256), ссылка `https://t.me/<бот>?startapp=<токен>` (имя бота —
`FEELINGS_BOT_USERNAME`); отображение кодов FB00x/42501/22023 в ответы контракта.
Входит (A1): миграция 0004 — отзыв у `feelings_app` прямых прав в обход функций (BACKLOG Б-13);
`app_issue_invite` требует онбординга — FB008 (0.7b-test D-4); обновление АР-13.
Не входит: бот и открытие Mini App по ссылке (1.4), экраны (1.5).

## Критерии готовности

- [x] RoadMap 1.3: тесты на повторное использование ссылки, истёкший срок, вторую пару (409/410 по контракту).
- [x] Все эндпоинты требуют `OnboardedUser`, кроме `GET /invites/{token}` (просмотр приглашения — после входа,
      но до онбординга, чтобы показать имя пригласившего); принятие — только после онбординга (FB008 → 403
      `onboarding_required`).
- [x] Ответы строго по схемам контракта (`Couple`, `InviteCreated`, `Error`); 404 не различает «нет» и «нет доступа».
- [x] В `Couple.members` — имена через `app_couple_members`, `is_me`; посторонний пару не видит.
- [x] Токен не попадает в логи, в БД хранится только хеш; ответ `GET /invites/{token}` не раскрывает ничего,
      кроме имени пригласившего и срока.
- [ ] (A1) Б-13: у `feelings_app` нет прямых UPDATE `couples`, `couple_members`, INSERT/UPDATE `invites`; xfail-тесты
      Б-13 в `test_couple_functions_a8.py` проходят (пометки снимает A8 в раунде проверки).
- [ ] (A1) D-4: выпуск ссылки без онбординга/после отзыва 18+ → FB008; xfail `test_issue_invite_requires_onboarding` проходит.
- [x] Полный сценарий по HTTP: Анна создаёт пару → ссылка → Игорь (после онбординга) смотрит и принимает →
      оба видят активную пару → выход → оба могут создать новую.

Заметки A2: эндпоинты — `backend/app/api/couple.py`, слой доступа — `backend/app/repositories/couples.py`
(только функции БД, прямых INSERT/UPDATE пар и приглашений нет — готово к отзыву прав Б-13), токен —
`backend/app/core/invites.py`, фильтр журнала доступа uvicorn — `backend/app/core/logging.py`; настройка
`FEELINGS_BOT_USERNAME` (без неё сервис не стартует). Коды ответов: FB001/FB007/22023 → 404 `not_found`,
FB002 → 410 `invite_expired`, FB003 → 410 `invite_used`, FB004 → 409 `own_invite`, FB005/23505 → 409
`already_in_couple`, FB006 → 409 `couple_not_pending`, FB008 → 403 `onboarding_required`, 42501 → 401.
Неверный формат токена в пути → 404 (не 422). `GET /couple` без активного членства → 404.
