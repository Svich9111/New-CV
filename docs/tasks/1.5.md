## Границы

Входит (`frontend/`):

- Подключение официального SDK Telegram Mini Apps (`telegram-web-app.js` в `index.html`) и типизированная обёртка
  `src/telegram/webapp.ts`: initData, `start_param`, тема, MainButton, BackButton, HapticFeedback, выбор чата
  (`t.me/share/url`), событие `activated`.
- Вход: initData → `POST /auth/telegram`; токен сессии только в памяти объекта `Api` (ни localStorage, ни
  sessionStorage, ни cookie); 401 на защищённом пути — один повторный вход и один повтор.
- Тема Telegram light/dark → `data-theme` на `<html>` → токены `theme.css`; смена темы на лету; цвет шапки и фона
  Telegram и цвета MainButton берутся из токенов.
- Вне Telegram (нет SDK или пустой initData) — экран «Открой в Telegram», запросов входа нет; «Помощь» доступна.
- Маршрутизация — стек экранов, связанный с BackButton (`src/app/App.tsx`, `routes.ts`); в клиенте без нативной
  BackButton (Bot API < 6.1) и вне Telegram — кнопка «Назад» в странице.
- API-клиент `src/api/client.ts`, типы — **генерация** из `api/openapi.yaml` (openapi-typescript 7.13.0,
  `npm run gen:api` → `src/api/schema.d.ts`; файл не правится руками; `npm run lint` проверяет, что он совпадает с
  контрактом). Обработка 401 / 403 / 404 / 409 (`conflict_retry` — один повтор, АР-24) / 410 / 422 / 429
  (`Retry-After`) / 5xx / обрыв связи: `ApiError` с текстом на «ты» по коду (`src/api/messages.ts`).
- Экраны: Приветствие (3 слайда), Онбординг (имя, обращение, имя партнёра, три согласия, 18+), Приглашение
  инициатора (создание ссылки, «Отправить в Telegram», «Скопировать», «Новая ссылка», статус «Ссылка готова» /
  «Ждём партнёра», опрос пары раз в 10 с и при возврате в Telegram), Входящее приглашение по `startapp`
  (имя пригласившего и срок до онбординга — АР-17; «Принять» → приветствие → онбординг → принятие), «Вы пара»,
  «Только с 18 лет», «Не получилось войти», «Помощь» (`GET /help/contacts`, запасной 112).
- Ссылка «Помощь и контакты служб поддержки» — на каждом экране, включая «Открой в Telegram» и ошибку входа.
- Дизайн-токены: **все цвета, шрифты, размеры шрифта и радиусы — в `src/theme.css`**, стили экранов
  (`src/app.css`) используют только `var(--…)` (проверяет `src/theme.test.ts`). **Дизайн оператором не утверждён
  (гейт Г1)**: взят стиль прототипа 0.6, базовые токены совпадают с `prototype/styles.css`
  (проверяют `theme.test.ts` и `prototype/check.mjs`, шаг 1). Смена дизайна после Г1 — правка `theme.css`;
  тёмная тема прототипа — АР-18 (ждёт Г1).

Не входит: главный экран и чат (2.2), профиль и выход из пары (4.x), подписка (4.4), тексты правил и согласий
(юрист, §9.4), проверенный список служб помощи (АР-33), сервер и деплой; проверка на телефоне — оператор (стыковка
с сервером на стенде, Г2).

## Критерии готовности

- [x] SDK: внутри Telegram — `ready()`, `expand()`, тема по `colorScheme`, подписка на `themeChanged`; вне Telegram —
      экран «Открой в Telegram» без запросов входа.
- [x] Вход по контракту: тело `{init_data}` как есть, без Authorization; токен только в памяти; 401 → повторный вход
      и один повтор, без цикла; 401 / 403 / 503 / обрыв связи при входе — причина подписью, повтор там, где помогает.
- [x] Онбординг: «Продолжить» (MainButton) недоступна и не отправляет запрос, пока не заполнены три поля и не отмечены
      все четыре пункта (три согласия и 18+); причина — подписью под формой; поля ≤ 64 символов; тело
      `PUT /me/onboarding` по схеме `OnboardingRequest` (с `timezone` устройства); 403 `underage` → экран «только с 18 лет».
- [x] Приглашение инициатора: после онбординга — `POST /couple` и ссылка со сроком; «Отправить в Telegram» открывает
      выбор чата; статус «Ссылка готова. Ещё не отправлена.» / «Ждём партнёра.» — текстом, не только цветом;
      пара стала активной → «Вы пара».
- [x] Приглашение партнёра по `startapp`: имя пригласившего и срок до онбординга; принятие — только после онбординга;
      404 / 410 `invite_expired` / 410 `invite_used` / 409 `already_in_couple` / `own_invite` — понятный текст и
      «Продолжить без приглашения»; токен неверного формата — без запроса.
- [x] Нативные элементы Telegram: MainButton (одна на экран, недоступная — серая из токенов, защита от двойного
      касания 500 мс), BackButton, тактильный отклик (`impact` на нажатие, `notification` на успех/ошибку).
- [x] Красный акцент — только MainButton и сердце (знак близости); ошибки — нейтральная рамка, значок «!» и
      подпись «Ошибка:» для экранного диктора (`theme.test.ts`).
- [x] Доступность: у полей, флажков и кнопок есть доступные имена; ошибки — `role="alert"`, статусы — `role="status"`;
      фокус на заголовке нового экрана.
- [x] Приватность: initData и токен не пишутся в консоль (правило ESLint `no-console`, тесты падают при любом выводе в
      консоль), в хранилища браузера, в DOM; запросы `credentials: "omit"`, `cache: "no-store"`.
- [x] `npm run lint` (eslint + tsc + свежесть типов API), `npm test`, `npm run build` — зелёные; прототип 0.6 не
      сломан (`prototype/check.mjs` — 202/202).
- [ ] Проверено в Telegram на телефоне оператором (после стыковки с сервером на стенде — Г2).
- [ ] Макеты утверждены оператором (Г1); при изменении — правка `theme.css`.

   прототипа). Клиент показывает свои тексты по `code`; предложение — зафиксировать в контракте, что `message`
