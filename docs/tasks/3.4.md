## Границы

Входит (`frontend/`):

**Чат (дополнение 2.2).** Кнопка «Подготовить сообщение» (§8): видна при активной паре; выделяется, когда в `done`
пришло `suggest_draft: true`. Нет активной пары — кнопки нет (или подпись «Пара ещё не создана»).

**Черновик** — маршрут `draft`, экран `src/screens/Draft.tsx`:
- `POST /drafts` (тело `{reply_to_id}` при ответе) — «Агент готовит черновик…»; 201 `Draft` — текст в поле правки;
  200 `DraftCrisis` — текст протокола целиком и контакты помощи (`tel:`, 112 всегда), черновика нет, ничего не
  смягчено (§9.3); 409 `couple_not_active` — «Пара не активна»; 422 `no_turns`, `bad_reply_target`, `draft_quote`,
  `blocked_by_safety` — свои тексты; 503 — понятное сообщение, разговор цел, «Повторить» (§10, АР-27).
- Пометка: «Черновик видишь только ты. Пока ты не нажмёшь „Отправить“, партнёр ничего не получит» (§2 п.2).
- Правка текста (предел 4000, пустой не отправляется); правка сохраняется `PATCH /drafts/{id}` с `expected_version`
  перед отправкой (или при уходе с экрана — реши и опиши); 409 `version_conflict` — перечитать `GET /drafts/{id}`,
  показать актуальный текст, **ничего не отправлять**; 409 `not_editable` — черновик уже отправлен/отклонён.
- «Другой вариант» — `POST /drafts/{id}/regenerate` (поле «пожелание», до 500, необязательно); если автор правил
  текст — подтверждение «Твоя правка пропадёт»; 422 `same_variant`; 200 `DraftCrisis` — протокол, прежний черновик
  не меняется; 503 — прежний текст на месте.
- «Отправить» — **только явное нажатие** MainButton «Отправить <имя партнёра в дательном>» (и запасная кнопка в
  странице): `POST /drafts/{id}/send` с `expected_version` показанной версии; двойное нажатие — один запрос; 202
  `PartnerMessage` (`processing`) — переход в ленту, сообщение со статусом «Обрабатывается»; 409/422 — свои тексты,
  ничего не отправлено; 402 — не отдаётся до этапа 4 (обработать как незнакомый код).
- «Не отправлять» — `POST /drafts/{id}/reject` (204, повтор 204) — возврат в чат.
- Id черновика — только в памяти сессии (как `ChatSession` 2.2); текст — не в хранилищах браузера.

**Лента пары** — маршрут `messages`, экран `src/screens/Messages.tsx`:
- `GET /couple/messages` (первая страница, «Показать более ранние» по `next_cursor`; 422 по курсору — с первой
  страницы без повтора курсора, как в 2.2); пустая лента и лента после выхода из пары — объяснение.
- Отправленные (`outgoing`) — свой оригинал и статус подписью: «Обрабатывается» (`processing`), «Доставлено»,
  «Прочитано», «Отвечено», «Не доставлено» (`withheld`) с причиной по Б-86 / АР-44: `safety` — «Не отправлено» и
  протокол помощи по `withheld_crisis` (`threat_outgoing` — «объяснить причину, вернуться к разговору»,
  `self_harm`, `life_threat`, `violence`, `null` — общий; контакты — `GET /help/contacts`, 112 всегда); `model_refusal` —
  подпись и ссылка на «Помощь»; `pipeline_error` / `attempts_exhausted` — «Не доставлено» и путь «подготовить
  заново» (см. АР-56 и «Изменения контракта» п.2); `couple_ended` — в ленте текущей пары не встречается.
- Полученные (`incoming`) — белая карточка с красной линией слева (§8); `is_adapted` — пометка «адаптировано»
  (знак и **подпись**, не только цвет); `harsh_tone_warning` — подпись «В оригинале резкий тон» (§6.2 п.6);
  «Показать оригинал» — `GET /couple/messages/{id}/original` (показ под карточкой, «Скрыть оригинал»; повторный показ
  без нового запроса в пределах сессии — реши; 409 `conflict_retry` — один повтор; `UnavailableText` — подпись);
  «Ответить с агентом» — переход в чат с контекстом ответа (АР-56), оттуда «Подготовить ответ» → `POST /drafts
  {reply_to_id}`; id входящего хранится при пузыре, а не общим флагом (Б-30).
- Прочитано: `POST /couple/messages/{id}/read` для полученных `delivered`, когда карточка показана на экране (одна
  отметка на сообщение; ошибка — молча, повтор при следующем показе).
- `UnavailableText` в ленте — «Текст недоступен», сообщение не скрывается.

**Главный экран** (`Paired.tsx`): «Сообщения пары» с числом непрочитанных полученных (по первой странице ленты:
`incoming` + `delivered`; подписью, не только кружком); вход в ленту.

**Общее**: методы в `src/api/client.ts`, строгие проверки `Draft`, `DraftCrisis`, `PartnerMessage`, страницы ленты;
тексты ошибок по операциям в `src/api/messages.ts`; заглушка `src/test/fakeApi.ts` — `/drafts*` (версии, конфликты,
кризис, 503, `same_variant`), `/couple/messages*` (две стороны пары, статусы, `withheld` с причинами, адаптированное и
нет, оригинал с фиксацией просмотра, прочитано, курсор и его смена); 401 — повторный вход.

Не входит: сервер; голос (2.3); подсказка ответа (`reply_hint`, Б-48); подписка и 402 (4.4); уведомления (3.5,
готово); «Профиль и пара»; живое обновление ленты (опрос сервера — см. вопрос 4).

## Критерии готовности

- [ ] ФТ-08, §2 п.2: `POST /drafts/{id}/send` уходит **только** после нажатия «Отправить» (MainButton или запасная
      кнопка) — тест: генерация, правка, «Другой вариант», «Не отправлять», уход с экрана, «Назад», перезапуск сессии —
      ни одного вызова `send`; двойное нажатие — один вызов; `expected_version` = версия на экране.
- [ ] Правка автора не теряется: 409 `version_conflict` — показан актуальный текст, ничего не отправлено; 503 при
      генерации и «Другом варианте» — прежний текст/разговор на месте (§10).
- [ ] Кризис (`DraftCrisis`, `withheld_reason: safety`) — протокол целиком, контакты (112 всегда), ничего не смягчено,
      черновика нет (§9.3).
- [ ] Лента: отправленные — свой оригинал и статус подписью (все 5 статусов, все причины `withheld_reason`);
      полученные — версия для получателя, пометка «адаптировано» подписью при `is_adapted`, «В оригинале резкий тон»
      при `harsh_tone_warning`; курсор и 422 по курсору; пустая лента.
- [ ] «Показать оригинал» — запрос `/original` только по нажатию (тест: показ ленты не вызывает `/original`), текст
      оригинала показан отдельно от адаптированного.
- [ ] Прочитано — одна отметка на показанное полученное `delivered`; своё отправленное не отмечается.
- [ ] «Ответить с агентом» — чат с пометкой ответа на это сообщение; «Подготовить ответ» шлёт `reply_to_id` именно
      этого сообщения и на втором входящем — второго (Б-30).
- [ ] Главный экран — число непрочитанных подписью; вход в ленту.
- [ ] Тексты (черновик, лента, оригинал) — только текст React; нет `dangerouslySetInnerHTML`; XSS — текст; в консоль,
      хранилища, cookie, адрес — не попадают.
- [ ] Доступность: статусы и пометки — текстом; итог отправки и ошибки — `aria-live`/`role="alert"`; доступные имена.
- [ ] Нативные элементы: MainButton «Отправить …» на черновике, BackButton; отклик `impact`/`notification`.
- [ ] Красный — только MainButton, сердце и линия карточки партнёра (§8); ошибки и «не доставлено» — нейтрально
      (`theme.test.ts`).
- [ ] `npm run lint`, `npm test` ×2, `npm run build` — зелёные.
- [ ] Макеты черновика, ленты, главного экрана утверждены (Г1).
- [ ] Стыковка с 3.2 и 3.3 на стенде и ключевой сценарий §1 на двух телефонах (Г2; полностью — гейт Г4, задача 3.6).

## Изменения контракта (A1)

Экраны делаются на текущем контракте. Отдельно — предложения A4/A0 к A1 (не блокируют начало, каждое — после
решения оператора по АР-56):

1. **Б-8** — «Ответить с агентом»: поле `reply_to_id` (id входящего) в `POST /chat/messages`, чтобы агент получателя
   разбирал именно это сообщение (§4.4 п.5); сейчас агент видит входящее только как одно из одобренных сообщений пары
   (§6.1 п.6).
2. **Б-86** — «Отправить снова» при `pipeline_error`/`attempts_exhausted`: в контракте нет способа повторно отправить
   тот же одобренный текст (новый черновик генерируется моделью). Варианты: `POST /couple/messages/{id}/resend` (новое
   сообщение из того же оригинала, автор подтверждает) или `POST /drafts` с `text` автора.
3. **Возобновление черновика**: нет `GET /drafts` (свой незавершённый черновик) — после закрытия приложения экран не
   найдёт черновик в статусе `draft` (в БД он остаётся). Предложение: `GET /drafts?status=draft` (последний).
4. **Б-79** — `Draft.text` только строка; нерасшифрованный черновик сейчас 404. Предложение — `ExportText`.

После любой правки контракта — пересборка `src/api/schema.d.ts` (её свежесть проверяет `npm run lint`).

## Вопросы оператору

1. АР-56: «Ответить с агентом» без Б-8 и «отправить снова» без Б-86 на первую версию — принять?
2. «Показать оригинал» — только у адаптированных (как прототип; у неадаптированных текст и так совпадает с
   оригиналом) или у всех полученных (контракт допускает)?
3. Когда сохранять правку черновика: перед «Отправить» (одним `PATCH`) или при каждом уходе с экрана?
4. Нужен ли опрос ленты, пока экран открыт (раз в N секунд), или достаточно обновления при открытии и по
   уведомлению бота (3.5 открывает Mini App без адреса экрана — открывать ли ленту, если есть непрочитанные)?
5. Текст на кнопке «Отправить»: с именем партнёра в дательном («Отправить Игорю») — откуда склонение (онбординг
   хранит `partner_name` в именительном)? Предложение — «Отправить» без имени до решения.
