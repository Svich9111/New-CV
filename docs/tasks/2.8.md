## Ограничения сейчас

- Макетов админ-панели нет ни в ТЗ §8, ни в прототипе 0.6 — стиль прототипа (`frontend/prototype/styles.css`,
  токены `src/theme.css`), простая вёрстка под компьютер; утверждение — вопрос оператору (Г1 или без макета).
- Стенда нет (Г2): страница проверяется на заглушке API (отдельная заглушка `/admin/*` по контракту); серверная часть —
  на тестовой БД.
- Настоящие книги — после решения оператора о правах (§6.4 «[уточняется]», Д4): в тестах — выдуманные тексты.
- Без кредитов модели отчётов прогона эталонного набора для новых версий нет (АР-26): у всех черновиков промптов статус
  «без прогона».

## Границы

**A4 (`frontend/`)** — отдельная точка входа, **не маршрут Mini App** (АР-52): `frontend/admin.html`,
`frontend/src/admin/**` (свой клиент API только к `/api/v1/admin/*`, без Telegram SDK и без клиента `src/api/client.ts`
пользователя); сборка — второй вход в `vite.config.ts`.
- Вход: поле «Токен администратора»; токен — только в памяти вкладки (не `localStorage`/`sessionStorage`/cookie/адрес);
  401 — снова поле токена; 403 `admin_only` — «Нужен токен администратора, а не вход через Telegram»; «Выйти» —
  забыть токен.
- **База знаний**: список материалов (название, автор, подход, основание прав, формат, размер, статус индексации
  подписью, код причины сбоя `index_error` → понятный текст, даты); «Обновить» (и/или опрос, пока есть `uploaded`/
  `indexing`); загрузка — форма multipart (файл, название, автор, подход, **основание прав — обязательно**), проверка
  до отправки: размер ≤ 20 МиБ, расширение pdf/epub/docx/txt; ответы 202, 409 `duplicate_document`, 413, 415, 422;
  удаление с подтверждением (204, 404 — уже удалён). Тексты книг и фрагментов не показываются (их и нет в API).
- **Версии промптов** — по решению АР-53: вариант (а) — таблица «роль — версия — активна в наборе — отпечаток — статус
  прогона», без кнопки активации; вариант (б) — то же плюс «Сделать активной» (только при приложенном прогоне; 409 —
  текст причины).
- **Метрики** — по решению АР-54: карточки показателей ТЗ §1 с целевыми значениями из ТЗ (подписью «цель ≥ …
  [уточняется]»); значение `null`/нет поля — «Недостаточно данных»; дата расчёта.
- Заглушка `frontend/src/admin/test/fakeAdminApi.ts` — по контракту, отдельно от `src/test/fakeApi.ts`.

**A1** — после решений оператора: контракт `/admin/prompts*` и `/admin/metrics` (см. «Изменения контракта»);
миграция функций метрик для `feelings_admin` (SECURITY DEFINER, только агрегаты, без id пользователей и пар, порог
малых групп; права — `REVOKE … FROM PUBLIC`, `GRANT EXECUTE … TO feelings_admin`); при варианте АР-53 (б) — функция
активации версии с записью `audit_log` (`prompt.activate`, без текста промпта). Миграция на общих стендах — после
подтверждения оператора (АР-4).

**A2** — обработчики `backend/app/api/admin_prompts.py`, `backend/app/api/admin_metrics.py` (вход — как в
`admin_kb.py`, подключение `admin_sessionmaker`, роль `feelings_admin`); `Cache-Control: no-store`; журналы без текстов.

Не входит: экраны с текстами переписок, памяти, черновиков, личного чата, `safety_events` по пользователям — **их нет
и не будет** (§9.1 п.5, критерий RoadMap); управление пользователями и парами; учёт стоимости модели на пару (§10 —
задача 4.7 / вторая очередь); редактирование текста промптов в панели (промпт меняется только новой версией файла и
прогоном набора — CLAUDE.md).

## Критерии готовности

- [ ] Критерий RoadMap «в панели нет ни одного экрана с текстами переписок»: (1) клиент панели обращается только к
      `/api/v1/admin/*` — тест по журналу заглушки на каждом экране; (2) в исходниках `src/admin/**` нет импорта
      пользовательского клиента и типов `ChatMessage`, `PartnerMessage`, `MemoryItem`, `Draft` (статический тест);
      (3) схема каждого ответа `/admin/*` в контракте не содержит полей с текстами пользователей; `Metrics` —
      `additionalProperties: false`, только числа/даты (тест контракта A1/A8); (4) сервер: под ролью `feelings_admin`
      SELECT из каждой личной таблицы §7 — отказ (Б-11; тест на тестовой БД).
- [ ] База знаний: загрузка с обязательным основанием прав; проверки размера и формата до отправки; все коды ответа
      — понятный текст; статус индексации и причина сбоя подписью; удаление с подтверждением.
- [ ] Токен — только в памяти; 401/403 — свои состояния; токен не попадает в журнал, консоль, адрес, хранилища.
- [ ] Версии промптов — по решению АР-53; активация (если есть) без отчёта прогона невозможна — тест сервера (409).
- [ ] Метрики — по решению АР-54: только агрегаты; при знаменателе ниже порога — `null` (тест сервера на выдуманных
      парах: 1 пара — значения нет); функции метрик недоступны `feelings_app`/`feelings_api`/`feelings_worker`/PUBLIC.
- [ ] Сервер: обработчики промптов и метрик под `feelings_admin`, сессия Mini App — 403, нет токена — 401 (тесты).
- [ ] `make lint`, `make test` (сервер), `npm run lint`, `npm test` ×2, `npm run build` (оба входа) — зелёные.
- [ ] Вид панели принят оператором (вопрос 1).

## Изменения контракта (A1)

1. `/admin/prompts`, `/admin/prompts/{id}/activate`, `/admin/metrics` — добавить ответы 401 `Unauthorized` и 403
   `AdminOnly` (как у `/admin/kb/documents`); `Cache-Control: no-store`.
2. `/admin/prompts*` — по АР-53: (а) `PromptVersion` = `{role, version, active, sha, eval_status (none|passed|failed),
   eval_report}` из файлов и конфигурации, `activate` — снять; или (б) `PromptVersion` + `eval_report_id`, `activate`
   — 409 с кодами `no_eval_run`, `eval_regression`, `already_active`, 404.
3. `/admin/metrics` — по АР-54: `additionalProperties: false`; все поля `type: [number, "null"]` (недостаточно
   данных — `null`); поле `computed_at`; при необходимости параметр периода; описание каждого показателя.
4. При желании A4 — `chunks_count` в `KbDocument` (сколько фрагментов проиндексировано) — необязательно.
