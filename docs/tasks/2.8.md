## Границы

**A4 (`frontend/`)** — отдельная точка входа, **не маршрут Mini App** (АР-52): `frontend/admin.html`,
`frontend/src/admin/**` (свой клиент API только к `/api/v1/admin/*`, без Telegram SDK и без клиента `src/api/client.ts`
пользователя); сборка — второй вход в `vite.config.ts`.
- Вход: поле «Токен администратора»; токен — только в памяти вкладки (не `localStorage`/`sessionStorage`/cookie/адрес);
  401 — снова поле токена; 403 `admin_only` — «Нужен токен администратора, а не вход через Telegram»; «Выйти» —
  забыть токен.
- **База знаний**: список материалов (название, автор, подход, основание прав, формат, размер, статус индексации
  подписью, код причины сбоя `index_error` → понятный текст, даты); «Обновить» (и/или опрос, пока есть `uploaded`/
  `indexing`); загрузка — форма multipart (файл, название, автор, подход, **основание прав — обязательно**), проверка
  до отправки: размер ≤ 20 МиБ, расширение pdf/epub/docx/txt; ответы 202, 409 `duplicate_document`, 413, 415, 422;
  удаление с подтверждением (204, 404 — уже удалён). Тексты книг и фрагментов не показываются (их и нет в API).
- **Версии промптов** — по решению АР-53: вариант (а) — таблица «роль — версия — активна в наборе — отпечаток — статус
  прогона», без кнопки активации; вариант (б) — то же плюс «Сделать активной» (только при приложенном прогоне; 409 —
  текст причины).
- **Метрики** — по решению АР-54: карточки показателей ТЗ §1 с целевыми значениями из ТЗ (подписью «цель ≥ …
  [уточняется]»); значение `null`/нет поля — «Недостаточно данных»; дата расчёта.
- Заглушка `frontend/src/admin/test/fakeAdminApi.ts` — по контракту, отдельно от `src/test/fakeApi.ts`.

**A1** — после решений оператора: контракт `/admin/prompts*` и `/admin/metrics` (см. «Изменения контракта»);
миграция функций метрик для `feelings_admin` (SECURITY DEFINER, только агрегаты, без id пользователей и пар, порог
малых групп; права — `REVOKE … FROM PUBLIC`, `GRANT EXECUTE … TO feelings_admin`); при варианте АР-53 (б) — функция
активации версии с записью `audit_log` (`prompt.activate`, без текста промпта). Миграция на общих стендах — после
подтверждения оператора (АР-4).

**A2** — обработчики `backend/app/api/admin_prompts.py`, `backend/app/api/admin_metrics.py` (вход — как в
`admin_kb.py`, подключение `admin_sessionmaker`, роль `feelings_admin`); `Cache-Control: no-store`; журналы без текстов.

Не входит: экраны с текстами переписок, памяти, черновиков, личного чата, `safety_events` по пользователям — **их нет
и не будет** (§9.1 п.5, критерий RoadMap); управление пользователями и парами; учёт стоимости модели на пару (§10 —
задача 4.7 / вторая очередь); редактирование текста промптов в панели (промпт меняется только новой версией файла и
прогоном набора — CLAUDE.md).

  «✓/…/!», не цвет), причина сбоя (`index_error` → текст по перечню воркера: `too_large`, `too_many_pages`,

## Предложения к контракту (A4 → A1)

1. `KbDocument` — `additionalProperties: false` (как для `Metrics`): закрепит в контракте, что в ответе нет текстов
   (клиент и так берёт только известные поля).
2. Необязательно — `chunks_count` в `KbDocument` (п.4 «Изменений контракта»).
3. Перечень кодов `index_error` в контракте (`enum` или список в описании, который ведёт A3) — сейчас тексты в
   `src/admin/texts.ts` сверены с `backend/app/kb/parse.py` и `workers/kb.py` вручную.
4. (A8 р.1 MINOR-2) Предел поля формы: сервер принимает текстовое поле не больше 64 КиБ (`MAX_FIELD_BYTES`), иначе
   Starlette отвечает **400 `http_error`**, которого нет в контракте; у `rights_basis` нет `maxLength`. Предложение:
   либо `maxLength` у `rights_basis` (в символах, с запасом под 64 КиБ UTF-8, например 16 000) и ответ 422
   `validation_error` при превышении, либо описать 400 в контракте. Клиент уже проверяет 64 КиБ в байтах до
   отправки и показывает понятный текст на 400 `http_error`.
5. Ответы `409 conflict_retry` и `500 internal` (общие для всех путей) — явно у `/admin/kb/documents*`.
