## Границы

Входит: модуль `bot/` (Python, общий `backend/pyproject.toml` или свой — обоснуй): приём обновлений через вебхук
(эндпоинт сервера с проверкой секретного заголовка `X-Telegram-Bot-Api-Secret-Token`), команда `/start` и
`/start <payload>` — ответ с кнопкой открытия Mini App (`web_app`), для `startapp`-ссылок Telegram открывает
Mini App сам — бот лишь отвечает на `/start`; кнопка меню Mini App; клиент Bot API с `sendMessage` для будущих
уведомлений (3.5) — без текста сообщений пары; устойчивость к повторной доставке обновлений (идемпотентность по
`update_id`); журналы без текстов и токенов.
Не входит: уведомления о сообщениях (3.5), оплата (4.4), реальная регистрация вебхука на стенде (0.8).

## Критерии готовности

- [ ] Вебхук отклоняет запросы без/с неверным секретным заголовком (401/403), сравнение за постоянное время.
- [ ] `/start` и `/start <любой payload>` → ответ с кнопкой Mini App; payload не попадает в журналы.
- [ ] Повторная доставка того же `update_id` не даёт второго ответа.
- [ ] Неизвестные типы обновлений и команды не роняют обработчик.
- [ ] Токен бота и секрет вебхука — только из окружения; без них сервис не стартует (как в 1.1).
- [ ] Клиент Bot API: таймауты, повтор на 429 с `retry_after`, ошибки не содержат токен (токен в URL Bot API!).
- [ ] Тесты без сети (подменённый транспорт).
