## Границы

Воркер конвейера (`app/workers/pipeline.py`): находит сообщения в `processing` (захват с арендой, `SKIP LOCKED`,
догон после перезапуска — A1 сделает функцию захвата, если существующих недостаточно), читает одобренный оригинал
(Б-39 — расшифровка с AAD черновика), `approve()` **только после проверки статуса черновика/сообщения в БД** (Б-48),
прогоняет `pipeline.process` (безопасность → тон → адаптация → смысл), доставляет `pipeline_deliver` или
останавливает `pipeline_withhold` (кризис, АР-27/28) с событием безопасности только типом; отказ модели расходует
одобрение (Б-48), недоступность — повтор после аренды, предел попыток — понятный исход для автора; одна транзакция —
одно сообщение, вызов модели вне транзакции, порядок блокировок (Б-45, АР-38); удалённый владелец — штатный исход (Б-44);
ключи шифрования в воркере (Б-42); подсказка получателю (`reply_hint`) не включается до прогона V2 (Б-48);
уведомление получателю — постановка задания для 3.5 без текста (Б-47: очередь хранит `user_id`).
Не входит: уведомления бота (3.5), экраны (3.4), выбор модели.

## Критерии готовности

- [ ] Текст сообщения не исполняется как инструкция (критерий RoadMap) — тесты на внедрение; решение о доставке и пометке — кодом.
- [ ] Агент получателя видит только одобренный оригинал; данных автора (диалог, память) во входе нет.
- [ ] Кризис — не доставляется (АР-28), автору — «не отправлено» и помощь (видно в ленте автора как `withheld`), событие только типом.
- [ ] Каждое сообщение обработано ровно один раз: гонки двух воркеров, перезапуск, удаление аккаунта отправителя/получателя, выход из пары.
- [ ] Время от отправки до доставки на заглушке — в пределах бюджета §10 (замер на модели — после кредитов).
- [ ] Журналы без текстов.
