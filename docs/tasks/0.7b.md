## Границы

Входит: новая миграция `0002_*` (не правка 0001): функции `app_accept_invite(p_token_hash bytea)`,
`app_leave_couple()`, при необходимости `app_issue_invite(p_token_hash bytea)` с отзывом прежней ссылки;
права EXECUTE только `feelings_app`; `SET search_path = public, pg_temp`, полные имена; downgrade.
Не входит: HTTP-эндпоинты (1.3), бот (1.4).

## Критерии готовности

- [x] `app_accept_invite`: принимает только приглашение `active` и с `expires_at > now()`; приглашение
      становится `used` (used_by, used_at) — повторно не используется; нельзя принять своё приглашение;
      нельзя, если у принимающего есть активное членство (одна активная пара, ФТ-04); пара должна быть
      `pending` и с одним активным участником; пара становится `active` (activated_at), принимающий — `partner`.
      Различимые коды ошибок (SQLSTATE свой класс, как FA00x в 0001) для: не найдено, истекло, использовано/отозвано,
      своё приглашение, уже в паре, пара не ожидает.
- [x] Гонка: два одновременных принятия одного приглашения — успешно ровно одно (блокировка строки).
- [x] `app_leave_couple`: текущий активный участник выходит (active=false, left_at); пара → `dissolved`
      (dissolved_at); все `active` приглашения пары → `revoked`; работает и для ожидающей пары инициатора.
      Агенты и личная память не затрагиваются (ТЗ §4.5 п.2). После выхода можно создать новую пару (ФТ-04).
- [x] `app_issue_invite`: только активный участник `pending`-пары; прежние active-приглашения пары → revoked;
      срок 7 дней ставит функция (ТЗ §4.1 п.6).
- [x] Миграция обратима; `alembic check` — модели и миграции согласованы.
- [x] Тесты под ролью `feelings_api` (фикстура `sessionmaker`) на каждый пункт, включая негативные.
