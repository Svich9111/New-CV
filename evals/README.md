# Эталонный набор (A3 + психолог)

> **Черновик A3 — ждёт утверждения психологом (Д5).** Гейты качества по набору не принимаются
> до утверждения (`docs/DECISIONS.md`, АР-15).

Задача 0.3. Цель — 100 ситуаций по уровням 1–5 (ТЗ §6.4, §10); этап 1 — первые 30.

| Файл | Что в нём |
| --- | --- |
| `schema.json` | JSON Schema формата ситуации |
| `situations/l<уровень>-<NN>-<тема>.yaml` | Ситуации: реплики владельца, ожидаемые уровень и стратегия, сообщение пары и недопустимые искажения, кризисный протокол |
| `RUBRIC.md` | Критерии оценки: автоматические проверки и оценка психолога |
| `QUESTIONS_FOR_PSYCHOLOGIST.md` | Вопросы психологу до утверждения набора |
| `run.py` | Прогон набора через интерфейс модели, отчёт markdown + json, сравнение с прошлым |
| `reports/` | Отчёты прогонов (`<дата>_<модель>.md/.json`) |

Все люди и события выдуманы. Конкретные контакты служб помощи в набор не вносятся.

## Запуск

```bash
cd backend && uv run python ../evals/run.py                 # заглушка, отчёт в evals/reports/
cd backend && uv run python ../evals/run.py --fail-on-regression   # код 2, если хуже прошлого
cd backend && uv run pytest -q tests/test_evals.py           # схема, покрытие, работа скрипта
```

Модель по умолчанию — детерминированная заглушка `stub` (не оценка качества). Настоящая модель
подключается адаптером над `backend/app/ai/llm/` как `--model пакет.модуль:Класс`: класс с
атрибутом `name` и методом `respond(EvalRequest) -> EvalResponse` — агент владельца (см. `run.py`).
Необязательно: `deliver(DeliveryRequest) -> DeliveryResponse` — агент получателя, вход только
одобренный оригинал (ТЗ §6.2); `converse(EvalRequest) -> [EvalResponse]` — ответ после каждой
реплики (ключевой сценарий по шагам); `pop_metrics()` — время, токены, стоимость по ситуации.
Запрос модели собирается только из данных владельца и сообщения пары; `partner_private_context`
и ожидания модели не передаются.

Коды выхода `run.py`: 0 — отчёт записан; 1 — ошибка набора или `--baseline` не найден; 2 — хуже
прошлого при `--fail-on-regression`; 3 — модель не загрузилась, прогон прерван фатальной ошибкой
или модель не ответила ни на одну ситуацию (отчёт не пишется); 4 — отчёт записан, но на части
ситуаций модель не ответила (они «не прошли» с причиной). `--blind` скрывает имя модели в md для
слепой оценки экспертом. База сравнения по умолчанию — последний по дате прогона отчёт той же
модели в `--out-dir` (если его нет — последний любой).

Какие отчёты коммитятся: `reports/2026-11-21_stub.{md,json}` (проверяется тестом
`test_committed_report_is_current`) и отчёты сравнения моделей. Локальные прогоны лучше писать в
`--out-dir` вне репозитория. После правки набора или `run.py` пересоздайте отчёт заглушки:

```bash
cd backend && uv run python ../evals/run.py --label 2026-11-21_stub --no-compare
```

Вопросы к психологу — `QUESTIONS_FOR_PSYCHOLOGIST.md`.

## Сравнение моделей (задача 0.4, предварительно — АР-19)

Нужен ключ Claude API в окружении (`ANTHROPIC_API_KEY`, только переменная окружения, не в
файлах репозитория). Без ключа обе команды завершаются с понятной ошибкой и кодом 3, отчёты не
пишутся.

```bash
cd backend && uv run python ../evals/compare.py                     # Opus, Sonnet, Haiku подряд
cd backend && uv run python ../evals/compare.py --models adapters.claude:Opus adapters.claude:Haiku
cd backend && uv run python ../evals/run.py --model adapters.claude:Sonnet   # одна модель
```

| Файл | Что в нём |
| --- | --- |
| `adapters/claude.py` | Адаптер `Opus` / `Sonnet` / `Haiku`: вызов агента владельца и **отдельный** вызов агента получателя только по оригиналу сообщения (ТЗ §6.2) |
| `adapters/openrouter.py` | Адаптер OpenRouter (0.4b, АР-22): `adapters.openrouter:<id модели>`, та же логика шагов; в каждом запросе `data_collection: deny` |
| `compare.py` | Прогон нескольких моделей и сводная таблица `<дата>_compare.md/.json` |
| `../prompts/compare.v1.md` | Системный промпт сравнения — только для 0.4, не промпт продукта (v0 — первая версия) |

Коды выхода `compare.py`: 0 — все модели ответили; 3 — модель не загрузилась, прогон прерван
фатальной ошибкой (ключ, лимит расходов) или какая-то модель не ответила ни на одну ситуацию; 4 —
частичные ошибки модели; 5 — прогон остановлен потолком расходов `--max-cost-usd` (по умолчанию
$15, до превышения). Отчёты уже прогнанных моделей сохраняются.

Модели разных поставщиков — через OpenRouter (ключ `OPENROUTER_API_KEY`; в облачном окружении его
подставляет прокси, в переменной — заглушка `proxy-injected`):

```bash
cd backend && OPENROUTER_API_KEY=proxy-injected uv run python ../evals/compare.py \
  --models adapters.openrouter:anthropic/claude-haiku-5.5 adapters.openrouter:openai/gpt-5.6-terra \
  --max-cost-usd 15
```

Потолок резервирует на каждый вызов наибольшее из: самый дорогой вызов модели в прогоне и верхняя
граница по прайсу (весь вход по цене входа + 16000 токенов по цене выхода).

Пересчёт сохранённых ответов текущими автопроверками — без вызова моделей и без расходов (файлы
перезаписываются, исходные остаются в истории git; набор должен совпадать):

```bash
cd backend && uv run python ../evals/compare.py --rescore ../evals/reports/<сводка>.json
```

Сводка: доля автопроверок по уровням, автопризнаки кризисного протокола, p50/p95 времени ответа,
$ на ситуацию и на 30 ситуаций (прайс — `backend/app/ai/llm/pricing.py`). «Кризис распознан»
(ТЗ §12 п.6) считается только по оценке эксперта. Окончательный выбор основной и резервной
модели — после утверждения набора психологом (Д5, АР-15, АР-19).
