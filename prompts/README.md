# Промпты агентов продукта (A3)

Каждая версия — отдельный файл `<назначение>.v<N>.md`: заголовок для людей (роль, разделы ТЗ,
модель, код, вход и выход) и блоки `<!-- prompt:<блок> --> … <!-- /prompt:<блок> -->` — модели
отправляется только текст блока. Изменение промпта — **новый файл версии** (старый не правится)
и прогон эталонного набора `evals/` с отчётом в `evals/reports/`; без прогона слияния нет
(CLAUDE.md). Версии, с которыми работает код, задаёт `PromptSet` в `backend/app/ai/prompts.py`
(каталог можно сменить переменной `FEELINGS_PROMPTS_DIR`).

## Кризисные шаблоны (`crisis.vN`) — не промпты модели

`crisis.v1.md` — блоки `crisis.v0` без изменений и блок `not_sent` («не отправлено», первым в ответе
автору, если одобренное сообщение остановлено по строке, обращённой к пострадавшему; АР-28, ревью
MAJOR-1, R2-MINOR-1). Шапка — «на утверждение психологом и юристом». Это фиксированный текст для
человека, а не вход модели: прогон эталонного набора на моделях его не проверяет (модель его не
видит), поэтому проверка — полным текстом ответа в тестах и прогоном набора на заглушке
(`evals/reports/2026-11-21_stub.md`). АР-26 (прогон моделей) к нему не относится.

По умолчанию остаётся `crisis.v0`: набор `V0` — все роли v0, это закреплено тестами A8 и АР-26
(«V0 — прототип 0.5»), а смена версии в нём меняла бы набор, по которому сделан прогон v0. Строку
`not_sent` код берёт из `crisis.v1` и для `V0` (в `crisis.v0` такого блока нет), так что текст
протокола лежит только в шаблонах, а не в коде. `V1` и `V2` используют `crisis.v1` целиком.
Если главная строка `outgoing_threat` (действует сам автор — в остановленном сообщении или по оценке
агента в чате), блоки для пострадавшего (`violence`, `life_threat`) не добавляются ни в одной
версии — это решает код (`crisis.VICTIM_TYPES`, ревью R2-MAJOR-1).
